# PLAN: 他の人のカーソルを表示する(websocket presence)

整理日: 2026-09-09。着手はまだ。`PLAN-live-edit.md` の議論から派生した。

## 背景

- 入力中の保存(PLAN-live-edit.md)で、端末→ブラウザの向きは PAT だけで
  リアルタイムに動く。sid が速くするのはブラウザ→端末の向きだけ
  (3 秒ポーリング→サブ秒)で、ひとりで書く用途では差が出ない。
- 同時編集で実害になるのは遅れそのものではなく、同じ行を同時に触って
  409 になり読み直しが走ること。Web 版はこれを**他の人のカーソル表示**で
  人が避けられるようにしている。競合を防ぐ仕組みではなく、避けるための情報。
- この表示は commit と同じ socket.io の room に流れる `cursor` イベントで
  実現されている。**cookie(sid)認証しか通らない**ので、PAT だけの環境では
  原理的に作れない。sid が実質的に必須になる用途はこれが最初になる。

## 現状

- `rust/src/ws.rs` は room に join して `commit` だけを扱い、`cursor` は
  未知イベントとして読み捨てている(冒頭コメントと `Recv::Packet(_) => {}`)。
  受信自体は既に届いている。
- 自分のキャレット位置を room へ送る(emit)ことはしていない。ブラウザ側から
  見ると cosentty の利用者は「いない」扱い。

## 目的

1. sid ありのとき、同じページを開いている他の人のカーソル(誰が・どの行に)を
   ページ上に出す。
2. 自分のキャレット位置を room へ送り、ブラウザ側の人にも見えるようにする。
3. sid なしでは何も出さず、何も送らない(縮退。フッターの `sync: poll` が理由)。

## 要確認(実装前に実測)

- `cursor` イベントの中身。既知の userscript 系の実装からは次の形が見込まれる
  が、**実フレームを `COSENTTY_DEBUG_LOG` 相当で採って確かめる**:

  ```
  42["cursor",{"user":{"id":"…","name":"…","displayName":"…"},
               "pageId":"…","position":{"line":N,"char":M},
               "visible":true,"socketId":"…"}]
  ```

  - `position.line` は**行番号(index)**で行 id ではない可能性が高い。だとすると
    ローカルの行と食い違う瞬間(自分の未保存の分割・結合の直後)があり、
    行 id へ翻訳できないので「その時点の行番号」として扱う。
  - `visible:false` はカーソルが消えた(ブラウザのフォーカス外・離脱)の意味か。
  - 送信側: ブラウザは emit `cursor` を何をきっかけに(キャレット移動ごと? 
    一定間隔?)どの頻度で送っているか。頻度は自分が送るときの上限にする。
- room に入っているのが自分だけのとき、`socketId` で自分のエコーを除けるか。
- ページ遷移時(room:leave→join)に相手のカーソル状態をどう捨てるか。
  join 直後に相手の現在位置は届くのか(届かないなら次の移動まで見えない)。

## 方針

### 受信

- `ws.rs`: `cursor` を `WsEvent::Cursor { user_id, display_name, page_id,
  line, char, visible, socket_id }` に起こして UI スレッドへ渡す。
  他の未知イベントは引き続き読み捨てる。
- `App` に `remote_cursors: HashMap<socket_id, RemoteCursor { name, line,
  char, seen: Instant }>` を持つ。`visible:false`・一定時間(例 30 秒)更新なし・
  ページ遷移・切断で消す。
- 描画: 相手のいる行のガター(テロメアの隣)に短い印を出し、名前は行の右端か
  フッターに出す(`👤 shokai` のような1語)。行番号は自分の `app.lines` の
  範囲に clamp する。色はユーザーごとに固定のパレットから選ぶ。
  行を占有するような描画(枠・帯)はしない。EDIT の見え方を邪魔しないため。
- 同じ行に自分のキャレットがあるときだけフッターに「同じ行を編集中: name」と
  出す。これが 409 を避ける実用上の核心。

### 送信

- `WsRequest::Cursor { line, char, visible }` を追加し、UI スレッドから ws
  スレッドへ渡して emit する。
- 送るのはキャレット行・桁が変わったときで、ブラウザの実測頻度を上限に間引く
  (少なくとも 1 秒に数回以内)。EDIT を抜けたら `visible:false`。
- READ のカーソル行も送るかは実測後に決める(ブラウザは選択なしでも送っている
  はず。同じにするのが自然)。
- 送信は sid ありで room に join できたときだけ。`SyncState::Live` 以外では
  何もしない。

### 縮退

- sid なし・切断中・再接続中: 表示も送信もしない。既存のフッター表示
  (`sync: poll` / `再接続中`)以外は増やさない。

## テスト計画

- `cursor` フレームのパース(実採取した JSON をそのままテストデータにする)。
- 同一ページ以外・自分の socketId のイベントは無視される。
- `visible:false` と時間経過で消える。ページ遷移で全部消える。
- 行番号が範囲外のとき clamp され、panic しない。
- 送信の間引き: 連続移動で emit が上限を超えない。EDIT 終了で visible:false。
- sid なしのセッションでは受信・送信のどちらも起きない。

## 完了条件

- ブラウザで同じページを開いた別ユーザーの位置が、端末側で行単位に見える。
- 端末側のキャレットがブラウザに他の人のカーソルとして見える。
- 同じ行にいるとき、フッターに相手の名前が出る。
- sid なしでは挙動が変わらず、既存テストがすべて通る。

## 実装順

1. 実フレームの採取(`cursor` の受信例と、ブラウザが送る emit の例・頻度)。
2. 受信のパースと `WsEvent::Cursor`、`App::remote_cursors`(表示なし)をテストで固める。
3. ガターの印とフッターの「同じ行」表示。
4. 送信(`WsRequest::Cursor`)と間引き。
5. KEYMAP の「リアルタイム同期」節と `NOTE-websocket-sync.md` に追記。
