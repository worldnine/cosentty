# SPEC: モードレス編集セッション

cosense web の編集体験（行ごとの編集・キャレット行だけソース表示・保存という概念がない）を
TUI に移植する。READ（閲覧シェル）と EDIT セッションの2状態で、**セッションの内側は
cosense web と同じく完全モードレス**。セッションは1行で終わらない——↑/↓ で行を渡り歩き、
Enter で行を増やしながら、何行でも連続して編集できる。

## 1. 状態モデル

```
READ（閲覧シェル: j/k・リンク・タイムマシン・コメント・関連ページ）
  │ e (行末) / i (行頭=インデント直後) / o・O (新行) / ダブルクリック (その文字位置)
  ▼
EDIT セッション（モードレス。何行でも連続編集）
  │ Esc / (READ 専用操作が必要になったら Esc で戻る)
  ▼
READ
```

- セッション中の dirty（未コミット差分）は**常にキャレット行の1行だけ**。
  これが衝突処理・救済・undo すべてを単純にする不変条件。
- 2026-09 から、キャレット行の文字入力は**打っている途中で保存**される（web と同じ
  リアルタイム反映。PLAN-live-edit.md）。dirty が残るのは、ページ未作成などで
  コミットを積めなかったときだけ。「行を離れた時のコミット」は、その残りを
  流す強制フラッシュとして今も同じ場所で呼ばれる。

## 2. READ モードのキー再編

**設計原則（KEYMAP.md）に従い `e` を akapen 本来の意味「編集」に戻す。**
`e`=ブラウザは「ブラウザが唯一の編集手段だった時代」の暫定割当だった。

| キー | 新 | 旧 |
|---|---|---|
| `Enter` / `f` | リンクを辿る（**変更なし**。二義性なし） | 同じ |
| `e` | セッション開始・キャレット**行末**（続きを書く） | ブラウザで開く |
| `i` | セッション開始・キャレット**行頭**（インデントの直後、vim の `I` 感覚） | 未使用 |
| `o` / `O` | 下/上に新行（**現在行のインデントを継承**）を作ってセッション開始 | コンポーザ起動 |
| `w` | ブラウザで開く（**w**eb。旧 `e`） | 未使用 |
| `u` / `^r` | undo / redo（§6） | 未使用（u は温存されていた枠） |
| `x` | READ では削除しない（案内のみ）。削除は EDIT の `^k`（行）と Shift+`↑↓`+`⌫`（範囲） | preview 付き削除 |
| `^e` | $EDITOR 全文編集 → diff → **即コミット**（ゲートなし） | preview 付き |
| `E` | 廃止（セッションに吸収） | 行編集コンポーザ |

- 確認ゲート（preview オーバーレイ）は**全廃**。preview API は dry-run 検証として
  内部で使い続けるが、ユーザーに確認は求めない。
- 関連ページ行（仮想行）では `e`/`i` は不可（ステータスで案内）。`o` はページ末尾に
  新行を作ってセッション開始。
- タイムマシン閲覧中はセッション不可（現行どおり read-only）。
- 認証済みでも閲覧先プロジェクトのメンバーでなければセッション不可。`e` / `i` / `o` / `O` /
  ダブルクリックは READ のまま留まり、編集権限がないことをステータスに表示する。

## 3. セッション内の挙動（モードレス）

| 入力 | 挙動 |
|---|---|
| 印字キー | キャレット位置に挿入（IME 経由の日本語もそのまま） |
| `←`/`→` `^b`/`^f` | キャレット移動（文字単位・char boundary） |
| `^a`/`^e` `Home`/`End` | 行頭/行末 |
| `^w` / `^u` | 直前の語を削除 / 行頭まで削除 |
| `Backspace` / `Del`・`^d` | キャレット前/後を1字削除 |
| `↑`/`↓` | **表示行単位**でキャレット移動（セッション継続）。折り返された行の中では同じソース行の次/前の表示行へ動き、端まで来たときだけ次/前のソース行へ渡る（そのとき dirty をコミット）。下へ抜けたら次行の先頭表示行、上へ抜けたら前行の最終表示行に着く。表示列は sticky |
| `Enter` | キャレット位置で**行分割**。行末なら新行作成。新行は現在行のインデントを継承し、キャレットはインデント直後へ。**セッションは継続**——そのまま次の行を書き続けられる |
| 行頭 `Backspace` | **前の行と結合**（キャレットは結合点へ）。タイトル行(0行目)では不可 |
| `Tab` / `Shift+Tab` | 行のインデント +1 / −1（行頭に空白を増減） |
| クリック | その行・その文字位置へキャレット移動（dirty ならコミット） |
| ホイール | ビューポートのみスクロール（キャレットは行を保つ） |
| `Esc` | dirty をコミットして READ へ |

- `q` はセッション中ただの文字。終了は READ からのみ。
- キャレットの上下移動は本文行の範囲内（関連ページ行には入らない）。

## 4. ローカルモデルの権威化（核心）

**lineId はクライアント生成**（`new_line_id()`、公式 CLI と同じ 12byte hex。
preview API はこの id をそのまま受理することを実測済み）。したがって:

- `app.lines`（id + text）が**唯一の真実**。挿入・分割・結合・削除・置換は
  まずローカルに適用し、画面は即座に再レンダリング。
- 新行の id は作った瞬間に確定する。**サーバーからのリロードを一切待たずに**
  次の編集（その行への replace、その行を anchor にした insert…）を積める。
- サーバーは背景で追いつく存在（§5）。リロードは 409 エラー時のみ。

これが「エディットモードのまま何行も続けて編集」を成立させる仕組み。
コミット待ちで手が止まることはない。

## 5. コミットポリシー

**直列コミットキュー**（背景ワーカー1本、mpsc）。同時送信は常に1つ、
後続はキュー待ち。各コミット = preview→submit の2リクエスト。UI は止めない。

| イベント | タイミング | ops |
|---|---|---|
| テキスト編集 | **入力中**（印字・⌫・Del・`^w`・`^u`・行内 `^k`・1行貼り付け・同一行の選択置換。最初の変更は即時、続きは 0.8 秒の静止か、連続入力中は前回送信から 3 秒で `flush_live_edit` が送る）。同じ行の未送信 replace は最新本文に**畳み込む**（worker が古い job を skip）ので、送るのは往復あたり1件。行を離れる時（↑↓/クリック/Esc/分割/結合の直前）の呼び出しは残りを流す強制フラッシュ | `replace(id, いまの本文)` |
| 行分割 | 即時 | `replace(cur, 前半)` + `insert(anchor=次行, 後半)` |
| 新行 (`o`/`O`/行末 Enter) | 即時 | `insert(anchor, インデント)` |
| 行結合 | 即時 | `replace(prev, prev+cur)` + `delete(cur)` |
| 行削除 (`x`) | 即時 | `delete(id)` × 範囲 |
| `^e` diff | 即時 | `diff_to_ops` の結果 |

- 構造イベントを即時に積むことで、キュー内の ops は常に「サーバーの（追いつき後の）
  状態に対して有効」になる。順序が正しさを保証する。
- 成功: ステータスに小さく `✓`。タイトルが変わって返ってきたら `app.title` を更新
  （タイトル行の replace = リネーム、サーバーの auto-suffix もここで反映）。
- 終了時 (`q`): キューを flush してから抜ける（未送信を失わない）。

## 6. undo / redo

確認ゲートの代替となる安全網。**コミット単位の逆演算**をスタックに積む。

| 実行 op | 逆演算 |
|---|---|
| `replace(id, new)`（旧テキスト保持） | `replace(id, old)` — lineId 不変 |
| `insert`（生成 id 記録） | その id を `delete` |
| `delete(id)`（旧テキスト・直後行の id 保持） | 元位置に `insert`（id は新規。逆演算スタック側の参照も張り替える） |

- `u` = undo（LIFO）、`^r` = redo。READ でもセッション中でも効く。
  セッション中は `u` が印字キーなので、undo は `^z`、redo は READ と同じ `^r`。
  `^z` は READ でも undo になるので、どちらのモードにいても同じ反射で戻せる。
  raw mode では ISIG が切れており `^z` は SIGTSTP にならない。ビューアに自前の
  suspend もないので、この割当で失うものはない。
- セッション中の undo は、まずキャレット行の dirty をコミットしてから 1 段戻す。
  「いま打った分が戻る」＝直感どおりの単位になる。キーごとに保存していても
  undo の単位は変えない：同じ行への連続入力（typing run）の undo エントリは
  最初の1つに畳み込み、行を離れる・構造編集・undo/redo で run を閉じる。戻したあとはキャレット行を
  **lineId で座り直す**（undo を跨いで生き残るのは index ではなく id）。
- **多段 undo でセッションを閉じない**。キャレット行を作った地点を越えて戻ると
  その行自体が消えるが、キャレットは**上の行の末尾**へ落ちて編集を続けられる
  （一般的なエディタと同じ振る舞い）。抜けるのは `Esc` だけ。
- **undo/redo はキャレットを「変わった場所」へ運ぶ**。元居た場所へ戻すのではない。
  行内の位置は、変更前後のテキストの共通接頭辞・接尾辞を除いた**変更部分の末尾**。
  打った分が戻るときはその手前、戻ってくるときはその末尾に着く。行そのものが消える
  undo では、繰り上がってきた行の先頭（繰り上がる行が無ければ直前の行の末尾）。
- undo 1 回はコミット 1 件。サーバに undo は無いので逆演算を送るしかないが、
  ローカルは即座に戻り、送信は直列キューが順に処理するので連打しても待たされない。
- undo/redo 自体もローカル適用 + コミットキュー投入（=履歴にも残る）。
- サーバ側の更新を取り込むとき（poll / ws 全同期）は、**まだ再生できる履歴を残す**。
  op が名指す lineId がページにあればそのエントリは有効、無ければそのエントリだけ捨てる。
  以前は更新のたびに undo/redo を全捨てしていたため、3秒ポーリング環境では
  web 側の編集 1 回で redo が黙って消えていた。捨てたときはステータスに
  「web 側の更新で失効しました」と出す（無言で効かないのと区別できるように）。
- スタックはプロセス内。さらに遡る場合はタイムマシン（将来: 「この版に戻す」=
  スナップショット + `diff_to_ops`）。

## 7. 表示

- **キャレット行だけ生ソース**を `wrap_line` で折り返して表示（source モードと同じ
  見た目、行番号なし）。他の行はビューの描画を維持。テーブル行なら
  そのテーブル行の描画部分が生テキスト行に置き換わる。
- **ハードウェアカーソルをキャレット位置に置く**（`Frame::set_cursor_position`）。
  端末の IME はハードウェアカーソル位置に変換窓を出すので、これが日本語入力の
  アンカーになる（akapen composer と同じ手法）。
- 行を離れてローカル適用された変更は即再レンダリング（コミット完了を待たない）。

## 8. IME（日本語前提）

- セッション開始 → `ImeGuard::enter(jp)`（自動で日本語）。
- セッション中は矢印・Enter・Backspace しか制御キーを使わないので IME ON のままで
  一切困らない。
- `Esc` → guard drop → 英数（次の j/k が必ず効く）。
- コメントコンポーザ（`c`）は現行のまま。

## 9. 衝突と救済

- 409 NotFastForward がワーカーから返ったら:
  1. キャレット行の buf と lineId を退避
  2. ページをサーバーから再読込（ローカルモデルを破棄して同期し直す）
  3. 同じ lineId が生きていればその行でセッション継続（buf を復元）
  4. 行が消えていれば buf を**救済バッファ**（Insert コンポーザ・anchor=_end・
     プリフィル）に落とす。**書いた文章は絶対に失わない**
- キュー内の未送信 ops は破棄（再読込後の状態が正）。ステータスで通知。
- その他のエラー: ステータス表示。ローカルは維持（次のコミットで再同期を試みる）。

## 10. マウス

| 操作 | READ | セッション中 |
|---|---|---|
| シングルクリック | リンク上ではリンク先へ移動。それ以外ではカーソル移動 | キャレットをその位置へ |
| **ダブルクリック** | **その文字位置でセッション開始**（cosense web に最も近い動線） | 同左（単なる移動） |
| ドラッグ | 範囲選択（現行） | v1 では範囲選択なし（コメントは READ で） |
| ホイール | ビューポート（現行） | 同じ |

## 11. 実装フェーズ（目安）

1. キー再編 + `w`/`e` 入替、コンポーザ式編集の撤去準備
2. EditSession（caret・行内編集・行移動・分割/結合/Tab）+ ローカルモデル権威化
3. 直列コミットワーカー + 行離脱コミット + 構造イベント即時コミット
4. キャレット行の生ソース表示 + ハードウェアカーソル（IME アンカー）
5. undo/redo
6. 409 リカバリ + 救済バッファ
7. マウス（ダブルクリック・クリックでキャレット）
8. `x`/`^e` のゲート撤去（undo 前提に変更）
