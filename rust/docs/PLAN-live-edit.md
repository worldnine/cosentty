# PLAN: Web に近いリアルタイム編集

整理日: 2026-09-09。

## 目的

EDIT セッションで英語などの確定済み文字を入力したとき、Web 版と同じように
入力中の変更がほぼリアルタイムでサーバーへ反映されるようにする。
画面上の編集はこれまでどおりローカルモデルへ即時反映し、保存はバックグラウンドで
行う。通信待ちで入力を止めない。

## 現在の前提

- `EditSession` はキャレット行の `input.buf` だけを未コミット状態として持つ。
- 通常の文字入力はローカルバッファだけを変更し、行を離れる時または `Esc` で
  `session_commit_dirty` を呼ぶ。
- 保存は `preview_edit` → `submit_edit` の2リクエストで、直列コミットキューを通る。
- `Enter`、行結合、行削除、字下げなどの構造編集は現在も即時コミットする。
- WebSocket の自己エコー除去、409競合時の再同期、未送信キューの順序保証が既にある。
  入力単位保存ではこれらを壊さないことを優先する。

## 方針

### v1: 確定済み文字の入力ごとに保存する

通常の印字入力、Backspace、Delete、単語削除など、ローカルの1回の編集操作を
サーバー上の1つの `replace(lineId, text)` として保存キューへ積む。

ただし、同じ行に対する未送信の `replace` はキュー内で単純に増やさず、最新の本文へ
畳み込めるようにする。これにより「a」「ab」「abc」を3件の独立した保存として
送るのではなく、サーバーが処理可能な範囲で最新状態へ追いつかせる。

入力イベントごとに必ずHTTP通信を完了させる必要はない。UIスレッドはキュー投入後に
戻り、ワーカーが順番を守って送信する。

### IME は段階的に扱う

英語などの確定済み入力は先にリアルタイム保存の対象にする。IMEの変換中テキストを
保存しないため、端末から未確定状態を識別できるかを確認する。

識別できない環境では、IME入力だけは現在の「行を離れた時」保存に戻すか、短い
デバウンスを挟む。日本語入力まで入力単位へ寄せることは、この確認後に決める。

## 実装計画

### 1. 入力イベントと保存境界を分離する

- `session_type_char`、削除、貼り付け、選択範囲置換を「本文が変わった」という
  共通経路へ集約する。
- `EditSession` に、最後にキューへ渡した本文または保存世代を記録する。
- 構造編集の直前に、入力単位保存の保留分を先に確定する。
- `session_commit_dirty` は、未保存差分がある場合の強制フラッシュとして残す。

### 2. 同一行のコミットを畳み込む

- 直列キューのジョブにページ、行ID、本文、世代を持たせる。
- 同一行について、まだワーカーが送信していないジョブは最新本文へ置き換える。
- 送信中のジョブは変更せず、その後ろに最新状態を1件だけ残す。
- 行分割・結合・削除など構造編集は畳み込まず、既存の順序どおり独立したジョブにする。
- undo/redo は既存どおり1操作1コミット単位とし、入力単位の履歴粒度もテストで確認する。

### 3. 自己エコーとリモート更新を検証する

- 入力直後に次の文字入力、Enter、上下移動が来るケースを再現する。
- 自分の古い `replace` エコーが、より新しいローカル本文を上書きしないことを確認する。
- 同じアカウントのWeb編集は自己エコーとして捨てず、外部更新として取り込む。
- キャレット行を編集中に届いた更新は既存のガードで保留し、入力の確定後に順序どおり適用する。
- 409が発生した場合は、現在の入力を失わずに再同期・再送できることを確認する。

### 4. IME の実測と保存条件を決める

- macOSの日本語IMEで、変換開始、変換中、確定、確定直後の各イベントをログで確認する。
- 確定イベントを安全に取得できる場合は、確定単位で保存する。
- 取得できない場合は、IME中だけデバウンスまたは行離脱保存にする。
- 英語入力、数字、記号、Backspaceは先にWeb相当のリアルタイム保存とする。

### 5. 表示と負荷を調整する

- 保存開始・成功の通知を文字入力ごとに表示せず、既存の静かな同期表示を使う。
- 429応答時も入力を止めず、既存のリトライと直列キューで追いつく。
- キュー長、送信中、未同期状態を必要な場合だけステータスへ表示する。
- 実測でリクエスト数が過大なら、入力単位を維持したまま短いデバウンスを設定できるようにする。

## テスト計画

- 1行への連続入力で、最終本文がサーバーに反映される。
- 入力中にEnter、上下移動、Esc、クリックを挟んでも本文が欠落しない。
- 連続入力が不要に大量の同一行ジョブを作らない。
- 送信中の古いジョブと後続の最新ジョブの順序が保たれる。
- Web編集、WebSocket自己エコー、409競合、再同期を組み合わせても入力が復元される。
- undo/redo、行分割、行結合、貼り付け、選択範囲置換が従来どおり動く。
- 日本語IMEの変換中テキストを誤って保存しない。
- `cargo test` 全体を実行し、既存のWebSocket同期テストと編集テストを green にする。

## 完了条件

- 英語を入力すると、入力を続けている間もWeb側から見てほぼリアルタイムに反映される。
- 入力処理はネットワークの遅延や429で止まらない。
- Enterやページ移動の直後に、直前の入力が古いエコーで巻き戻らない。
- 日本語IMEについて、実装した保存境界と未対応条件が仕様として明記されている。
- 既存の編集、同期、undo/redo、競合回復のテストがすべて通る。

## 実装順

1. 入力変更の共通経路と保存世代を追加する。
2. 同一行の未送信ジョブを最新本文へ畳み込む。
3. 英語・確定済み文字で入力単位保存を有効にする。
4. 自己エコー、構造編集、競合回復のテストを追加・修正する。
5. 日本語IMEのイベントを実測し、確定単位保存または例外扱いを決める。

## 実施記録（2026-09-09）

### 実装

- 保存境界: `handle_session_key` の末尾と1行貼り付けの末尾で `session_commit_dirty`
  を呼ぶ。キャレット行のバッファを変える操作はすべてここを通るので、個別の
  入力関数には手を入れていない。本文が変わっていなければ何もしない。
  構造編集・行移動の直前にある従来の呼び出しは強制フラッシュとして残した。
- 畳み込み: mpsc のキューはそのまま。`App::live_superseded`
  （`Arc<Mutex<HashSet<CommitJobId>>>`）を worker と共有し、同じ行への新しい
  ライブ job を積む直前に、前の未送信 job（`App::live_pending`）の id を入れる。
  worker は取り出した直後、送信前にこの集合を見て、含まれていれば送らずに
  `Skipped` を返す（`inflight` の数え方は変わらない）。印が付くのが取り出しの後
  でも、古い本文→新しい本文の順で送られるだけで正しさは変わらない。
  構造編集は別 job なので畳み込まれず、順序どおり送られる。
- undo の粒度: 同じ行への連続入力（typing run）は undo エントリを最初の1つに
  畳み込む（`App::live_undo`）。行を離れる、構造編集、undo/redo、セッション終了で
  run を閉じる。結果として「行を離れた時に1コミット」だった頃と undo の単位は同じ。
- 自己エコー: 既存の `own_commits` 照合と `inflight > 0` のガードで足りる。
  ws のエコーは保存が返って `Done` が処理されるまでバッファされ、その後 id で
  捨てられる。打ち続けている間は `inflight` が 0 にならないのでリモート更新も
  待たされるが、フッターに「保存を待っています」と理由を出すようにした。
- 429: `send_edit_polite` 等は触っていない。既存の直列キューとリトライで追いつく。

### IME について

- 端末（crossterm）には変換中の文字列（preedit）は届かない。Ghostty・kitty 等は
  preedit を端末側で描き、確定した文字だけをキーイベントとして渡す。したがって
  変換中テキストが保存される経路は存在せず、確定単位保存が自然に成立する。
- 確定時は複数文字が1フレームで連続して届く。1文字ごとに job を積むが、worker が
  最初の1件を送っている間に残りは畳み込まれるので、実際の通信は 1〜2 件になる。
- デバウンスは入れていない。実機で通信量が問題になったら、`session_commit_dirty`
  の呼び出しをフレーム末尾に寄せるのが最小の変更になる。

### テスト

- `live_typing_saves_each_keystroke_and_supersedes_the_older_ones`
- `live_typing_keeps_order_across_a_split_and_a_line_change`
- `the_worker_skips_a_superseded_job_without_sending_it`
- 「入力だけではコミットしない」前提だった6件のテストを新しい前提に書き換えた。

### 追記(2026-09-09、実測後)

- 126 キーの連続入力を実機で流したところ、畳み込みで送信は 10 件に収まったが、
  途中で 7 秒の空白が出た。1+2+4 秒のバックオフと一致し、preview+submit の
  2 リクエスト × 往復ごとの送信で Cosense の burst 制限(429)を踏んでいた。
  worker が眠っている間は「同期が止まった」ように見える。
- 対応: `session_live_commit` で間引く。run の最初の変更は即時、以後は 0.8 秒の
  静止(`live_debounce`)か前回送信から 3 秒(`live_max_wait`)の早い方で
  `flush_live_edit`(イベントループの毎周)が送る。構造編集・行移動・Esc は
  従来どおり即時に流す。テストは `page()` がデバウンスを 0 にして従来の断言を保つ。
