# NOTE: 米印の大きさをどう見せるか(mdfried 方式の調査と、`*N` 印の決定)

2026-09-08。mdfried(https://github.com/benjajaja/mdfried)のように見出しを
実際に大きな文字で描くアプローチを cosentty に持ち込めるか調べ、当面は
米印 5 個以上に個数の印を添える方式に決めた記録。

## Cosense の米印は Markdown の見出しではない

`[* ]` は 1 個ごとに 1.2 倍ずつ文字が大きくなる**連続的な文字サイズ装飾**。
10 個まで効き(`[***** ]` ≈ 2.5 倍、`[********** ]` ≈ 6 倍)、行頭でなく
文中にも置け、`/` `-` `_` と混ぜられる。Markdown の 6 段階とは別物なので、
「空行や罫線で見出しらしさを出す」類のセル装飾では差を表せない。

cosentty はテーマの `markup.heading.1..4.markdown` を 4 個までに対応させて
おり、この範囲はうまく行っている。問題は 5 個以上が最上位に丸められて
見分けがつかないことだけだった。

## mdfried がやっていること

起動時に端末の能力を見て 2 系統を切り替える。

- **Kitty Text Sizing Protocol(OSC 66)**: 端末に「s 倍で描け」と頼む。
  文字は本物のまま、フォント不要、キャッシュ不要。`big_text.rs` は
  1 セルにエスケープ列を詰めて残りを Skip にするだけ。倍率 1〜7 と分数
  n/d を組み合わせられ、1.2^n の連続スケールと相性が良い。文字が本物なので
  編集中もそのまま大きく出せる。
- **画像化**: cosmic-text でラスタライズし ratatui-image の
  `SlicedProtocol` で kitty/sixel/iTerm2 に出す。同梱フォントは Cascadia と
  JetBrains Mono(CJK なし)。別スレッド生成、テキスト+レベルでキャッシュ。
  どちらも無ければ chafa。

## cosentty で採用する場合の評価

下地はほぼある。`Row::height()` が多段行を扱い、`build_image` と
`App::images` のキャッシュ、ワーカースレッド、編集中の行を生テキストへ戻す
`content_view` の分岐(`src == eline`)が、そのまま流用できる
(NOTE-webrender-handoff.md がテンプレ)。ratatui-image 11 は
`Capability::TextSizingProtocol` の問い合わせに対応済み。

障害は次の通り。

1. **OSC 66 を描ける端末は事実上 Kitty だけ**(2026-09)。Ghostty は
   PR #10315 で解釈だけ入り、中のテキストを捨てる(issue #10333 は 1 月から
   更新なし、作者は「contributor friendly ではない」と明言)。foot は幅指定
   のみ。WezTerm / iTerm2 / Windows Terminal は未着手。Cosense の利用者層
   (日本語圏、Mac/Windows)にはほぼ届かない。
2. **画像化は日本語フォント**が要る。同梱すると crate が数 MB 膨らむので、
   やるなら fontdb で OS のフォント(Hiragino / 游ゴシック / Noto CJK)を探し、
   無ければ現状に落とす。
3. **編集との相性**。画像の上にカーソル帯・選択・検索ハイライトは乗らない
   (画像行と同じ制約、`ui.rs` の `SlicedImage` 描画のコメント参照)。編集に
   入るとその行が生テキストの通常サイズに縮み、抜けると膨らむ。行の高さが
   変わるのでスクロール位置の保持が要る。
4. **tmux / SSH** は画像も OSC 66 も不安定。NOTE-mmd-text.md で「テキスト層
   を画像より優先」と決めた理由がそのまま当たる。

## 決定: 5 個以上に `*N` を添える

- 4 個以下: テーマの見出し書式のまま(変更なし)。
- 5 個以上: 本文の直後に半角スペースを挟んで `*5`〜`*10` を、見出し色の
  DIM で添える。行頭でも文中でも同じ。`x10` ではなく `*10` にしたのは、
  記法そのものの延長として読めるから。
- 編集中の行は生テキスト表示なので印は出ない(米印が直接見える)。
- 実装は `render/inline.rs` の `star_level_marker` 1 箇所と、それを呼ぶ
  `decorate_bracket` の装飾分岐 2 つ、`render.rs` の `parse_heading`。

端末・tmux・SSH を問わず動き、編集に影響せず、半日規模。画像化を後で
入れるなら「5 個以上は画像、出せない端末ではこの印」と、同じ境目で切れる。

## 後で画像化するなら

- しきい値は米印 5 個(≈2.5 倍、2 行を超える)。4 個以下はセルのまま。
- フォントは OS のものを fontdb で探す。無ければ `*N` 印に落とす。
- 色は web と同じくテーマの文字色+太字で足りる。星ごとの色分けは TUI 独自
  の代替表現だったので、サイズが出るなら要らない。
- 文中の装飾は `layout_inline` の「ベースラインから上へ伸びる箱」に乗る。
- Ghostty が OSC 66 を描けるようになったら、画像化より先に OSC 66 の道を
  検討する(小さく作れ、編集中も大きいまま)。
