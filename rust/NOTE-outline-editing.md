# アウトライン編集

## 結論

アウトライン編集は、画像貼り付けと切り分けて先に実装する。行／選択範囲とブロック、上下左右を一組として設計する。機能を「ブロックだけ」「左右だけ」に狭めない。

上下移動の保存方法は、2026-08-30に本家の通信を実測して確定した。本家と同じく、動かす行を削除し、新しい行IDで移動先へ挿入する。周囲の行は更新しない。

## 本家に合わせる操作

| 入力 | 対象 | 動作 |
|---|---|---|
| `Ctrl+↑` / `Ctrl+↓` | 現在行、または選択した連続行 | 直前／直後の行と入れ替える |
| `Ctrl+←` / `Ctrl+→` | 現在行、または選択した連続行 | 対象だけを1段浅く／深くする |
| `Alt+↑` / `Alt+↓` | 現在行を根とするブロック | 同じ親を持つ前／次の兄弟ブロックと入れ替える |
| `Alt+←` / `Alt+→` | 現在行を根とするブロック | 子孫を含めて1段浅く／深くする |

ブロックは、根の行と、それに続く「根より深い行」の最大連続範囲とする。表示上の折り返し行ではなく、ページのソース行を基準に判定する。

タイトル行は移動・インデントしない。選択中の `Alt` 操作は、対象が曖昧になるため受け付けない。`Ctrl` 操作は選択した連続行を1つの範囲として扱う。

コードブロックとテーブルを独自の保護領域にはしない。どちらもヘッダとインデントされた本文から成るため、ヘッダで `Alt` 操作をすれば全体が自然に動く。本文に対する `Ctrl` 操作は、通常の行操作として扱う。

## 編集セッションとの関係

アウトライン専用モードは作らない。READとEDITのどちらからも同じキーで操作できるようにする。

EDIT中に未確定の入力がある場合は、現在行を先に確定してから構造を操作する。操作後もEDITを保ち、カーソルを操作対象の論理行へ追従させる。IME変換中は構造操作を始めない。

`Tab` / `Shift+Tab` の既存動作は維持する。テーブル本文ではTabがセル区切りなので、アウトライン操作は修飾矢印を正本とする。

## 端末でキーが届かない場合

正本には、本家と同じ修飾矢印を使う。macOSや端末設定がキーを横取りする場合に備え、1打のプレフィックスから `h/j/k/l` を入力する予備経路も用意する。

既存の `Ctrl+O` はページ一覧と衝突するため使わない。`Alt+h/j/k/l` も、Escに続く文字入力との判別が曖昧になるため使わない。プレフィックスの第一候補は未使用の `Ctrl+G` とする。

```text
Ctrl+G h/j/k/l      行／選択範囲を左・下・上・右へ
Ctrl+G H/J/K/L      ブロックを左・下・上・右へ
```

プレフィックス入力中は、使えるキーをステータス行に表示する。Escまたは未対応キーで取り消し、後続キーを本文へ流さない。

## 保存方式の実測結果

検証ページは[アウトライン編集プロトコル実験](https://scrapbox.io/my-sandbox/アウトライン編集プロトコル実験)。ヘッドレスChromeから本家へキーを送り、同じページのWebSocket commitとREST APIの前後を記録した。

### `Ctrl+↑`は移動元だけを作り直す

`probe-root-b`を1行上へ動かすと、本家は次の2操作を送った。

```text
_delete 5c3247db85fcf2681a155c9c
_insert b10f1c6b36155ee30a72e94f  id=6a94522300000000006938c0 text="probe-root-b"
```

移動した行は新しい行IDになった。間をまたいだ行のID・本文・作成時刻・更新時刻は変わらなかった。リリースノートの「移動先の行の更新日時と行IDをupdateしない」はこの意味だった。

### `Alt+↓`はブロック全体を作り直す

子と孫を持つ3行のブロックを下へ動かすと、根・子・孫をそれぞれ`_delete`し、移動先の同じアンカーへ同じ順番で`_insert`した。3行とも新しいIDになり、入れ替わった兄弟ブロックのIDと時刻は変わらなかった。

### 左右移動は既存行を更新する

`Ctrl+→`は現在行だけに`_update`を送った。`Alt+→`は、根から「同じ深さ以下の行が現れる直前」までの各行へ`_update`を送った。すべての行IDと作成時刻を維持し、更新時刻だけが変わった。

以上から、現在の`page-edit-for-ai`で本家と同じ保存ができる。上下移動は移動元を`Delete`してから、移動先へ新しいIDで`Insert`する。左右移動は対象行を`Replace`する。sidは不要で、PATだけで全操作を保存できる。

「同じ表示結果になるから、行数の少ない側を動かす」という最適化はしない。本家も必ずユーザーが動かした側を作り直す。選んでいない行のID・履歴を変えないためです。

## 実装の分け方

1. インデントから行・ブロック・兄弟範囲を求める純粋なプランナーを作る。
2. キー入力とカーソル／選択範囲の追従を実装する。
3. 左右移動を既存の`Replace`へ落とし込み、undo／redoまで通す。
4. 上下移動は、移動元の`Delete`と新しいIDを持つ`Insert`へ落とし込む。
5. READとEDIT、IME、WebSocket自己エコー、競合時再同期の回帰テストを追加する。

構造操作は1つのコミット、1つのundo単位とする。保存待ちの構造操作がある間にキーを連打した場合も、古い行順を前提に複数の操作を送らない。

## 受け入れ基準

- `Ctrl`は現在行または選択範囲だけを動かす。
- `Alt`は根と子孫をまとめて動かす。
- 上下移動は兄弟単位で、親・子を飛び越えない。
- タイトル行を変更しない。
- 折り返し幅や画面サイズで対象範囲が変わらない。
- 空行、全角空白、タブ、深さを飛ばしたインデントでも結果が一定である。
- 操作後もカーソルと選択範囲が対象行へ追従する。
- 1回の`u`で元へ戻り、`Ctrl+R`でやり直せる。
- 保存失敗や競合時に、画面だけ成功した状態を残さない。
- 左右移動では行IDを維持する。
- 上下移動では動かした行だけを新しいIDにし、周囲の行IDと時刻を維持する。
- 修飾矢印が届かない端末でも予備キーからすべて操作できる。
