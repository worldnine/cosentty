# SPEC: テロメアの web 対応(状態の種類・太さの分解能)

作成: 2026-09-06。実装タスクは `PLAN-next.md` の「### 6. テロメアの web 対応」。

## 1. web 版の仕様(実測込み)

一次情報と実測:

- 公式ヘルプ `help-jp/テロメア`(`support-doc-jp/テロメア` も同内容):
  太い=新しい、**未読=青**(前回訪問以降に更新された行)
- 開発者本人 `shokai/テロメア`(橋本商会): 太さは現在時刻からの対数で
  `0h,1h,2h,6h,8h,12h,24h,72h,7日,30日,60日,90日,180日,約1年` の区切りごとに
  **1px ずつ細く、最小 1px で消えない**。「色・太さ・有無の3軸は多すぎる、
  2つで十分」の設計判断も明記。詳細は WEB+DB PRESS vol.102(2017-12)
- リリースノート 2022-11-24: 「テロメアを既読・未読・ロード後に更新の3色に分ける」
- **本物の app.css を実測**(2026-09-06、`https://scrapbox.io/assets/css/app.css`
  を取得して確認。社区の nrem-configs/テロメアの配色 の記述と一致):

| 状態 | セレクタ | 色 |
|---|---|---|
| 既読 | `.telomere-border` | `var(--telomere-border, #e2e2e2)` グレー |
| 未読 | `.unread:not(.updated-after-load)` | `var(--telomere-unread, #89a3ff)` 青 |
| ロード後更新 | `.updated-after-load` | `var(--telomere-updated, #6b8cff)` 濃い青 |
| 削除行(履歴) | `.will-delete-next` | `#fd7373` 赤(変数なし) |

実測で確定した細部:

- **優先順位**: 未読のセレクタが `.unread:not(.updated-after-load)` なので、
  両方のクラスを持つ行は**ロード後更新の色が勝つ**。すなわち
  after-load ⊃ 未読、表示優先は after-load > unread > read
- **`:hover` で幅が `auto` になり、相対時刻のチップ**(12px、白文字、
  背景 `#808b8c`)が出る。チップ部分は行 permalink でもある
- **削除行に打ち消し線は無い**。app.css 全体に `line-through` は1つもなく、
  `.will-delete-next` はテロメアの色だけ。削除行の本文は通常表示
- プロジェクトテーマごとに変数の上書きがあり、既定青系(`#89a3ff/#6b8cff`)と
  緑系(`#7fca8f/#47ba5f`)の2系統+テーマ別の亜種がある。TUI はテーマに
  依存しない方針(KEYMAP「テロメア・カーソル・選択の色はテーマに依存しない」)
  なので既定の青系に寄せる
- 太さの CSS 既定は `border-width: 0 0 0 5px`(左ボーダーがバー)。
  実際の太さは行ごとに JS が対数で決める(上記 shokai の記述)

未解決(web 側でも記述が見つからない):

- `.updated-after-load` → 未読への降格が「時間経過」の場合の基準。
  実装では「ページを開いている間は after-load のまま」を採る(下記 3.3)

## 2. TUI 現行の仕様(`rust/src/theme.rs::telomere`)

- 2軸: **太さ=年齢、色=未読か**。太さ6段 `<1h,<1d,<1w,<30d,<1y,≥1y`、
  グリフ `█▊▌▎▏▏`(`▉▋` が未使用で、末尾2段は `▏` を使い回し+色差)
- 色: 未読=青(年齢で最大 `UNREAD_FADE_MAX=0.45` までグレーへフェード) /
  既読=グレー(最古バケットは `faded_border_color` でさらに薄く)
- 関連ページ・インデックス一覧にも同じテロメア(web の一覧には無い、TUI の拡張)。
  日時を持たない項目(プロジェクト横断リンク)は最細グリフ
- web との差: 太さ 6段 vs 14段(当日の中の刻みが無い)、状態 2色 vs 3色、
  履歴の削除行表示なし

## 3. 決定した設計(2026-09-06、ユーザー決定含む)

### 3.1 太さ: 1列のまま 8グリフ・9状態

- **ガター2列化は却下**(80桁で本文1列減+波及を嫌う)。1列で取れる最大は
  左寄せブロック要素8種 `█▉▊▋▌▍▎▏`
- 区切りは web の14段を圧縮して 8グリフ+最古の色差で **9状態**:

  `<1h(█), <6h(▉), <24h(▊), <72h(▋), <7日(▌), <30日(▍), <180日(▎), <1y(▏), ≥1y(▏フェード)`

  web の `2h/8h/12h/60日/90日` を落とす(1セルでは14段は物理的に不可能なので、
  「当日を複数段に・対数的に・長期も残す」を優先した圧縮)
- 「端末によっては分数グリフが潰れて見えない」は許容する(ユーザー判断:
  潰れる端末でも `█▊▌▎` の骨格は残るので情報は失われない)
- 太さと色は同じバケットに從う(現行規約を維持)

### 3.2 色: 4状態(`theme.rs` に `TelomereState`)

| 状態 | 色 | 出る場所 |
|---|---|---|
| `Read` | 現行グレー(最古はフェード) | 全部 |
| `Unread` | 現行青+年齢フェード(維持) | 全部 |
| `UpdatedAfterLoad` | フェードなしの濃い青(未読より濃度が上。web `#6b8cff` 相当) | **NOW の本文のみ**(一覧・履歴には出ない) |
| `WillDelete` | 赤固定(`markup.deleted` と色見を合わせる。web `#fd7373`) | 履歴ビューのみ。**打ち消し線は付けない**(app.css 実測) |

既存の `(age, unread, light)` シグネチャは `Read`/`Unread` へのラッパとして
残し、一覧・関連ページの呼び出しは触らない。

### 3.3 ロード後更新(`UpdatedAfterLoad`)の判定と遷移

- 判定: `line.updated >= この訪問のオープン時刻`。`nav.rs` の `record_visit`
  に渡している now を `Loaded` に `open_stamp` として持たせるだけ。
  ws push・自分の編集エコーは `line.updated` を更新するので自動で入る
  (sync 側に追跡不要)
- 遷移: ページを離れる/`R` で取り直すと次回の `read_at` が今回の訪問に
  なるので自動で未読へ降格(web の「ページを閉じると未読に変わる」と一致)。
  web の「時間経過でも降格」は実装しない(§1 の未解決事項)
- 履歴閲覧中は未読の青も使わない(web は履歴では既読グレー+削除赤のみ)

### 3.4 履歴の削除行(`WillDelete`)

- 判定: **隣接スナップショットとの行 id 差分**。スナップショット i の行のうち
  i+1(より新しい方、末尾なら NOW の生ページ)に無い id = 次の版で消える
- `PageLine.id` はスナップショット応答にも載る(api.rs 確認済み)。
  i+1 はタイムマシンのスクラブで既に取得・キャッシュされるので追加リクエストは
  原則ゼロ。最古スナップショットより前は判定対象外

## 4. 対応表(web → TUI 実装後)

| web の状態 | TUI | 備考 |
|---|---|---|
| 既読 `#e2e2e2` | `Read` グレー | 対応 |
| 未読 `#89a3ff` | `Unread` 青+フェード | TUI だけ年齢フェード(web は一定色) |
| ロード後更新 `#6b8cff` | `UpdatedAfterLoad` 濃い青 | 遷移は「離脱時」のみ(§3.3) |
| 削除行 `#fd7373` | `WillDelete` 赤 | 打ち消し線なしで一致 |
| 太さ14段(1px刻み) | 9状態(8グリフ+最古色差) | 1セルの物理上限。区切りは§3.1 |
| hover で相対時刻チップ | 無し。`e`(行の詳細)と一覧の常時表示で代替 | UX は別物(今回は対象外) |

## 5. 実装順(1 worktree、テスト green ごとに ff)

1. 太さ8段化(区切りも同時。グリフの物理確認は下記)
2. 状態4色化(表示はまだ全部従来どおり)
3. ロード後更新(nav + ui + sync テスト)
4. 履歴の削除行(nav + ui + KEYMAP・ヘルプ追随)

実装前の実機確認: 手元端末で `echo █ ▉ ▊ ▋ ▌ ▍ ▎ ▏` を見て、分数グリフ
(`▉▋▍`)が塗り潰されず区別できるか。潰れるなら該当段を飛ばして7段に落とす
(その場合は `<6h` と `<24h` を統合する)。
