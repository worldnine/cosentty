# PLAN: モード体系と選択・カーソル表現の再設計

作成日: 2026-09-01。対象: `rust/src/bin/view/`(PLAN-view-split.md の分割後構成が前提)。
まだ実装していない。実装時はこの文書の「段階」を1つずつ、worktree + テスト green で進めること。

## 課題の整理 — 4つの症状は同根

ユーザーが挙げた課題:

1. SOURCE モードの位置付け: できることが少ないのに Tab という一等地を専有している
2. VIEW と EDIT の区別がつきにくい: 今どちらにいるのか作者でも分からない
3. VIEW の行複数選択が矢印(Shift+↑/↓)でしか伸ばせない。J/K が効かない
4. Tab によるセル区切りとの衝突感

根は1つ: **「モード」の重みと、キー・視覚言語の配分が釣り合っていない**。

現状の実測(コード確認済み):

- モードは実質3つ: VIEW / SOURCE(`Mode` enum、Tab でトグル)+ EDIT(`app.session` の有無)
- SOURCE で「しかできない」こと: 行番号つき raw 全文の閲覧のみ。web レンダは止まる
- VIEW⇄EDIT の視覚差は3点だけ: ①フッタ左端の小さな `VIEW`/`SRC`/`EDIT` タグ、
  ②ページ枠が EDIT で「消える」(無くなるのはサインとして気付きにくい)、
  ③EDIT ではハードウェアカーソルが置かれる(点滅は端末依存で控えめ)
- **`SEL_BG` と `CURSOR_BG` が同色(どちらも `Color::DarkGray`)**(ui.rs 冒頭の const)。
  選択 band とカーソル行 band が見分けられないのは、モード以前にこれが一因
- 選択拡張: `v` 開始→ j/k で伸ばせる。Shift+↑/↓ でも伸ばせる(`read_select_line`)。
  しかし **Shift+J/K は未割り当て**(`J`/`K` は移動モード中のみ使用)。ここの非対称が症状3
- Tab の過積載(症状4): VIEW=モード切替 / EDIT=インデント / 表の本文行=セル区切り(`\t` 挿入)/
  索引=ペイン切替。「表を編集したいのに VIEW で Tab を押してソースモードに落ちる」
  「選択中に Tab で選択が消える」という事故の構造がある

## 提案

### A. SOURCE を「モード」から「表示オプション」へ降格

- Tab から外し、**`s` でトグル**(READ 中のみ。`s` は現在未割り当てを確認済み)
- 位置付けを一言で定義: 「行番号つき raw の読み取り専用ビュー。コピー・記法デバッグ・
  行番号参照のためのもの」。ヘッダの `[ソース]` バッジと行番号ガター自体がモード表示を兼ねる
- 将来の廃止も視野に入れる: EDIT のキャレット行はすでに raw を見せるので、全画面 raw の
  残存価値は「行番号」と「ページ全体の raw コピー(Y)」だけ。行番号を VIEW の表示
  オプションにできたら SOURCE は消せる。今回は降格まで、廃止はしない

### B. Tab の再定義 — 1モード1意味に

- **VIEW: Tab / Shift+Tab = ページ内リンク巡回**(次/前のリンクへフォーカス、Enter で開く)。
  ブラウザの Tab と同じ意味論なので説明が要らない。巡回フォーカスは行カーソルを
  そのリンクの行へ運ぶ(既存の `links_at_src` / カーソル基盤に乗る)
- EDIT: 現状維持(インデント。表の本文行ではセル区切り `\t`)
- 索引: 現状維持(ペイン切替)
- 効果: 「Tab の意味がモードごとに1つ」になり、症状4の衝突感と選択消滅事故が消える

### C. モードの視覚署名 — 「どっちにいるか」を三重に

優先度順(1つでも効くが、重ねると迷わない):

1. **ハードウェアカーソル形状**: EDIT に入ったら `SetCursorStyle::BlinkingBar`、
   出たら元へ(READ は現状どおりカーソル非表示)。「点滅する縦棒が見える=編集中」
   という一次シグナル。IME アンカーとしての既存の hardware cursor 運用ともそのまま整合
2. **ページ枠を「消す」のではなく「色を変える」**: READ=現状の枠、EDIT=CHROME_ACTIVE
   (緑)の枠。状態の差分は「有無」より「色違い」のほうが気付ける
3. **フッタの mode タグをバッジ化**: EDIT のときだけ反転(緑地に黒字の ` EDIT `)。
   VIEW は現状の控えめな表示のまま

### D. カーソル/キャレット表現の役割分担

- READ の行カーソル: 淡 band(現状)を維持。ただし **`SEL_BG` と `CURSOR_BG` を分色**する。
  選択は「選択と分かる色」(テーマに沿った淡色)、カーソル行は現状の DarkGray。
  これだけで「どこまでが選択で、いまどこにいるか」が読めるようになる
- EDIT のキャレット: hardware の点滅バー(C-1)を主役にし、キャレット行の band は
  薄くするか消す(文字編集の邪魔をしない)。左フレーム列のキャレットマーカー
  (既存の `carets` 描画)は EDIT 色で維持
- 端末が cursor style に応えない環境(古い tmux 設定など)への fallback として、
  キャレットセルのソフト描画(reverse)をオプションで持つかは未決(下記)

### E. 選択キーの対称化(最小・即効)

- READ: **J / K = 選択しながら1行下/上**(`read_select_line` に接続。Shift+↑/↓ と同義)
- `v` 開始 → j/k 拡張は現状維持。Esc 解除も現状どおり
- 移動モード中の J/K(兄弟ごと移動)とは状態が違うので衝突しない(確認済み)
- KEYMAP.md の選択の節に「Shift+↑/↓ = J/K」と明記
