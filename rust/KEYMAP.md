# cosense-tui キーマップ

**設計原則: akapen のキー体系を正とし、cosense 固有の概念を akapen の「対応する枠」に割り当てる。**

akapen で身につけた指の動きがそのまま通用することを最優先する。新しい概念（ページリンク、
ページ履歴、ブラウザ）は、akapen で意味的に対応する枠（ファイル移動、ファイル一覧、編集）に
マッピングし、キーを新設しない。

## 起動

```
view                                        # 引数なしはプロジェクト一覧から（PAT の参加プロジェクト。無ければ help-jp）
view <project> [title]                      # title 省略時は最近更新されたページ
view https://scrapbox.io/<project>/<title>#<lineId>   # ブラウザの URL をそのまま。#行ID があればその行にカーソル
```

主なオプション。

| オプション | 意味 |
|---|---|
| `--lang ja\|en` | 画面の言語。省略時は `COSENSE_LANG` → `LC_ALL` → `LC_MESSAGES` → `LANG` を見て、どれも無ければ英語 |
| `--preview on\|off\|auto` | 一覧の抜粋欄（既定 `auto`＝80桁以上で表示） |
| `--download-dir DIR` | 保存先。省略時は `COSENSE_DOWNLOAD_DIR` → `XDG_DOWNLOAD_DIR` → `~/Downloads` → カレント |
| `--send-cmd CMD` | `s` で送るコメントの宛先（stdin にパイプ。`cat >> review.txt`、`xargs -0 -I{} herdr agent prompt w:p1 {}` など）。省略時は herdr の中なら**このタブの唯一のエージェント**（いなければワークスペースの唯一の）へ `herdr agent prompt` で直送、外なら送り先なし（`y` でコピー） |
| `--ime jp\|off` | IME の扱い（既定 `jp`） |
| `--theme NAME` / `--light` / `--dark` | 配色 |

## 日本語環境（IME）前提の操作体系

akapen と同じ Swift ヘルパ（Carbon TIS、アクセシビリティ権限不要）を内蔵し、
**コマンドモードは常に英数・入力欄は自動で日本語** を実現する：

- 起動時に英数へ強制（j/k 等が IME に食われない）。終了時は起動前の入力ソースを復元
- 入力欄（コメント `c`・挿入 `o`/`O`・行編集 `E`）を開くと**自動で日本語に切替**
  （既定 `--ime jp`。切替不要なら `--ime ascii`、何もしない `--ime off`）
- 入力欄を閉じる（Enter/Esc）と即英数に戻る —— 次の j/k が必ず効く
- 外部の `ime guard` デーモン（akapen のもの）とは suspend ファイルで協調
- ヘルパは `~/.cache/cosense-tui/ime-<hash>` に初回バックグラウンドビルド。
  akapen が同一ソースからビルド済みのヘルパ（`~/.cache/akapen/`）があればそのまま使う
- 万一コマンドモードに全角文字が届いたら、**その場で英数へ戻す**（`j`/`k`/`e`/`q` が
  このモードの言語なので、案内より復帰が先。日本語を打つのは EDIT の仕事で、そちらは
  入るときに自動で日本語になる）

入力欄は readline 風の行内編集に対応：`←`/`→`（`^b`/`^f`）カーソル移動 · `^a`/`^e` 行頭/行末 ·
`^w` 直前の語を削除 · `^u` 行頭まで削除 · `Del`/`^d` カーソル位置を削除。
日本語の文を途中から直せる（全消しして打ち直さない）。
コメント欄は**複数行**にできる：`Shift+Enter`（端末が kitty keyboard protocol を話すとき——kitty · WezTerm · Ghostty · iTerm2 · Alacritty 等。起動時に `supports_keyboard_enhancement` で確かめて DISAMBIGUATE を要求する）、`Alt+Enter`（ESC CR。古い端末でも届く）、`^j`（akapen の鍵。どこでも効く）のどれでも改行。Enter は保存。`↑`/`↓`（`^p`/`^n`）で
行の間を桁を保って移動、`^a`/`^e` はその行の頭と末尾。

## 認証

公式 CLI（`@helpfeel/cosense-cli`）の `cosense login` が保存した認証情報
（`~/.cosense/settings.json`）をそのまま使う。解決順序は CLI と同じ:

1. `COSENSE_PAT` 環境変数
2. `projects[]` の Service Account（origin + project 一致、`x-service-account-access-key`）
3. `users[]` の Personal Access Token（origin 一致、`x-personal-access-token`）
4. `COSENSE_SID` 環境変数（connect.sid cookie、レガシーフォールバック）

読み・書き・検索は 1〜3 だけで完結する。sid が必要なのは websocket push 同期(と、
既定でオフの web レンダラを上げたときの非公開ページ描画)だけ。無ければ縮退する
（`同期: poll` / レンダラを上げていなければ何も起きない）。

起動時のステータス行に `認証: pat`（英語表示では `auth: pat`）のように表示される。未認証なら公開プロジェクトの
読み取り専用（`cosense login https://scrapbox.io` で有効化）。非公開プロジェクトの閲覧・
編集・スナップショット・ファイル/画像取得のすべてがこの認証を通る。認証情報があっても、
現在のユーザーが閲覧先プロジェクトのメンバーでなければ `[読み取り専用]` と表示し、EDIT セッション・
新規行・削除・undo/redo・`$EDITOR` 編集には入らない。プロジェクト用 Service Account は編集可とみなす。

**リアルタイム反映（websocket push）**: `connect.sid` で認証しているときは
3秒ポーリングの代わりに websocket push 同期が動く（ステータス行に `同期: ws`）。
scrapbox.io の room に join し、commit イベントを `/socket.io/` の生フレームから
直接受信して行差分を即時適用する（ブラウザでの編集が**1秒以内**に画面へ。未読行は
テロメアで青く表示）。自分の編集のエコーは冪等適用で二重化しない。切断時は指数
バックオフで自動復帰。
PAT / Service Account のみの環境では従来どおり `同期: poll` の3秒ポーリング。

## cosense 固有の追加

### READのアウトライン編集

`Ctrl+矢印`は現在のソース行だけを操作する。連続行の選択中は、その範囲が対象になる。
`Alt+矢印`は現在行から始まるブロックを操作し、選択中は受け付けない。左右は1段の字下げ、
上下は隣の行／範囲や兄弟ブロックとの入れ替えになる。タイトル行は変更しない。上下移動では
対象だけを新しい行IDで挿入し直し、周囲のIDと時刻を保つ。

修飾矢印が届かない端末では、`Ctrl+G`に続けて`h/j/k/l`を押す。大文字の`H/J/K/L`は
ブロック操作になる。並びは左／下／上／右。`Esc`と未対応の2打目は取り消し、そのキーを
ほかの操作へ流さない。`Ctrl+O`は引き続きページ一覧に使う。

#### 移動モード（`m`）

READで`m`を押すと移動モードに入る。カーソル行を根とするブロックをつかみ、`Esc`か`Enter`を
押すまで動かし続けられる。中では修飾キーを使わない。

| キー | 動作 |
|---|---|
| `j` / `k` / `↓` / `↑` | ブロックを1行ずつ下／上へ。深さは変えない |
| `J` / `K` | 隣の兄弟ブロックをまとめて越える |
| `h` / `l` / `←` / `→` | ブロック全体を1段浅く／深くする |
| `Esc` / `Enter` / `m` | モードを抜け、動かした結果を1つのコミットとして送る |

つかんでいる間、矢印もブロックを動かす。目に見えて持っているものを、矢印が黙って手放して
カーソルだけ動かすのは、このモードで唯一避けたい驚きだから。`↓`／`↑`は`j`／`k`と同じ1行移動で、
`Shift`付きの矢印も同じ。`J`／`K`だけが「大きく飛ぶ」に割り当ててあり、`H`／`L`は`h`／`l`と同じ。
どの大文字でもコミットは飛ばない。

`j`／`k`はタイトルとページ末尾を越えないこと以外に制約がなく、上下は厳密な逆操作になる。深さは
変えないので、通り抜ける先が深い並びの中でも位置だけが動く。親から出るのは`h`の仕事で、
リストの外へは`h` → `j` → `l`で出せる。

`J`／`K`は兄弟のかたまりごと飛ぶので、節の並べ替えが速い。兄弟がない向きでは理由を出して
止まるが、`j`で1行ずつ行けるので行き止まりにはならない。以前は兄弟単位しか用意しておらず、
外へ出て入り直せば到達できる配置まで拒否していた。制約が守るものは無く、打鍵数だけを
増やしていた。

つかむブロックは入った時点の行集合で固定する。`h`で字下げを戻して下の行が子に見えるように
なっても、対象は増えない。

1行ずつ動くので、`code:`ブロックの本文の中にもブロックを置ける。操作中は1手ごとに画面へ出る
ので気づけるし、`Esc`で抜けてから`u`で戻せる。

モード中の移動は手元だけで行う。既存の行の並びと字下げを書き換えるだけなので行IDは変わらず、
サーバーへは何も送らず、undoも積まない。抜けるときに、入った時点との差分を1コミットとして
送る。位置と深さが元のままなら何も送らない。字下げだけが変わったときは`Replace`で行IDを保ち、
位置が変わったときは、そのブロックの行だけを削除して新しい行IDで挿入し直す。何回動かしても
`u`1回で元へ戻せる。保存が失敗・競合したときは、`m`を押す前のページに戻す。

つかんでいるブロックは選択範囲と同じハイライトで示し、フッターに`MOVE`と使えるキーを出す。
状態を色だけでは表さない。英語表示のフッターは
`MOVE — j/k line · J/K sibling · h/l indent · Esc commit`。全部の説明はヘルプに出す。
モード中はほかの編集とリモートの反映を、編集中の行があるときと同じように止める。止めている
間はフッターに「つかんでいるブロックを待っています」と出す。移動キー以外は、先にモードを
抜けて結果を確定してから効く。ボタンを押していないマウスの移動では抜けない（どの端末でも
ポインタの通過が届くので、それで確定してしまうと持っていたものが勝手に保存される）。カーソルと選択範囲は、
抜けたあとも動かしたブロックに付いていく。

EDITからは`Esc`で抜けて`m`と押す。修飾キーなし2打で届く。`Ctrl+G`と修飾矢印は別経路として
残してある。

アウトライン編集はEDITの中には置かない。編集セッションは文字を打つ場所で、組み替えは行を
選ぶ場所の仕事だから。EDIT中に`Ctrl+矢印`や`Alt+矢印`を押すと、何もせずに`Esc` → `m`を案内
する。素の矢印と同じ扱いでキャレットだけ動かすと、ブロックが動くと思った手が黙って空振り
するため。`Shift+矢印`の範囲選択はそのまま。

| **関連ページリスト** | （本文枠の下に常時表示） | cosense 本体と同じく、**本文枠を一度閉じた下側（枠外）**に `Links`（1-hop: 順リンク＋被リンク）・**リンクごとの 2 hop グループ**（存在しないページ経由でも成立）・`External links`（プロジェクト横断）を描画。各リンクのガターには**本文の行と同じテロメア**を表示する（太さ＝そのページの更新の新しさ、色＝未読か。未読の判定はこのTUIの訪問記録による）。以前は太さを使わず色だけで区別していたが、同じガター1列が画面によって別の意味になるのをやめた。日時を持たないエントリ（プロジェクト横断リンク。関連ページAPIが日時を返さない）は「新しい」と騙らず最も細い `▏` になる。**リンクに下線は引かず、色もリンク色では塗らない**（1行1リンクなので、どちらも全行に同じ印を付けるだけになる）。空いた色は**未読かどうか**に使う（テロメアが青／通常色で語る）。インデックスの一覧と同じ読み方になる。`G` は本文枠の最終行へ移動し、そこから j/k でそのまま Links へ降りていけ、`Enter` で開ける（ステータスは `link n/N` 表記）。view モードのみ。データは**ページ取得とは別リクエスト**の `relatedPages`(v2 の本文応答には載らない)なので、ページを開いた一拍後に下から現れる。**並び順はインデックスの `s` で選んだものに揃う**——各セクションの中をその順に並べ替え、セクション自体（Links → リンクごとの 2 hop → External links）の順は変えない（グループ分けそのものが情報なので）。関連ページAPIは `updated`/`accessed`/`created`/`linked` を持つので手元で並べ替える。`views` だけは返してこないので、そのときはサーバの順（updated の新しい順）のまま。タイトル横の薄い値もインデックスと同じく**並べている値**になる（`accessed`/`created` はその時刻の経過、`linked` は `linked 7` のように件数、`title`/`views` は更新の経過）。テロメアは並び順に関係なく更新の新しさ。並び順を変えたとき、下に開いているページの関連ページも取り直さずに並べ直す |
| リンクを開く | `Enter` / `f` | カーソル行のリンクへ。複数あればピッカーを開く。`[/project/ページ]` の**プロジェクト横断リンク**はそのプロジェクトのページを開き、**`[/project]`（ページ名なし）はそのプロジェクトのインデックスを開く**（cosense のホーム画面にあたるもの。以前は何も起きないリンクだった）。ヘッダは常に `プロジェクトの正式名称 / ページ`（正式名称が読めないときはスラッグ）。`[` で戻れる。`^o` のインデックスは今いるプロジェクトのページを一覧する |
| URL を開く | `Enter` / `f` | カーソル行の http(s) リンク（`↗`）を既定のブラウザで開く。`[タイトル URL]` はタイトル表示。gyazo 画像の行では `↗ gyazo` として**画像のページ**（`gyazo.com/<id>`、Teams は `<org>.gyazo.com/<id>`）を開く |
| **コード / テーブルを保存** | `Enter` / `f` | `code:名前` と `table:名前` の行はリンクになっている（**下線**が目印）。保存先ディレクトリに書き出して開く。Cosense にも `/api/code/…`・`/api/table/….csv` はあるが、**セッション cookie 専用でこのビューアの token では 401** になるため、**いま表示しているページから書き出す**（往復もせず、画面と中身が必ず一致する）。テーブルは RFC 4180 で CSV 化し、カンマ・引用符・改行を含むセルだけ引用符で囲む |
| ファイルを保存 | `Enter` / `f` | カーソル行の添付ファイル（`📎`、`[名前 https://scrapbox.io/files/….pdf]`）を保存先ディレクトリに書き出して開く。画像以外の拡張子を持つアップロードが対象で、ページリンクと混在する行はピッカーに両方並ぶ |
| **保存先ディレクトリ** | `--download-dir DIR` | 保存先は `--download-dir` → `COSENSE_DOWNLOAD_DIR` → `XDG_DOWNLOAD_DIR` → `~/Downloads` → カレントディレクトリの順に決まる。`~/Downloads` はあくまで候補の1つで、それが無いマシン（サーバーや最小構成の端末）でも、起動したディレクトリに黙って落ちることはない。フラグと環境変数で**指定した**ディレクトリは、無ければ作る（`~` も展開する）。作れなかった場合は起動時に理由と実際の保存先を表示する。XDG と `~/Downloads` は既存のときだけ使う |
| ページピッカー | `^o` | 最近更新順。`/` で絞り込み（移動は ↑↓ / `^n`/`^p`）。打った名前が既存ページに無いときは最下段に `＋ 「名前」を作成` が出る |
| **未作成ページのリンク** | （色で区別） | まだどこにも根付いていないリンクは**別の色**で描く（cosense web の赤リンクにあたる）。下線はそのまま——`Enter` で開けて、1行書けばその場で作られるのだから、押せることに変わりはない。カーソルを載せるとフッターにも `(未作成)` と出る。**判定は「ページがあるか」ではない**（本家の実装を読んで合わせた）。本家は全ページのリンクを走査して索引を作り、リンク先を『生きている』と印を付ける——**ただし、その語を書いているのが画面のページだけなら付けない**（`P !== p.Page.id && n.set(te, !0)`）。つまり赤は「ページが無い」ではなく**「このページ以外の誰もこの語を言っていない」**。2つ目のページがその語を使った瞬間、ページが無いままでも普通のリンク色になる。共有された語はもうハブだ、という考え方。同じ答えは手元のレスポンスから出せる：自分のリンク先を書いている他ページは、その語を自分と共有しているので必ず自分の 1hop / 2hop に居て、`linksLc` にその語を持っている。（villagepump/井戸端 で検証：素朴な「links1hop に居ない＝未作成」は4件を赤にするが、本家は3件。救われる `実況` は未作成だが他ページからリンクされている）判定は三択（生きている／どこにも無い／まだ聞いていない）で、塗るのは真ん中だけ。書いたばかりのリンクだけはレスポンスに載っていないので裏で1回問い合わせる（`HEAD /api/pages/<project>/<title>/text` が 200 なら書かれている。404 なら、そのタイトルのページ取得で**自分以外の被リンク**があるかを見る＝本家と同じ二段の問い）。**キャレット行は判定しない**——書いている途中の `[新` に聞いても意味がなく、その行は生ソース表示なので色も出ない。聞いていないものは通常色のまま。「未作成なのに普通の色」は放っておけるが、「実在するのに未作成の色」は嘘になるため。問い合わせは1タイトル1回きり（失敗しても再試行しない＝読めないプロジェクトでリクエストが湧き続けない）。**「生きている」はページをまたいで持ち越すが、「どこにも無い」は持ち越さない**——後者は「聞いたページ以外の誰も書いていない」という意味なので、次に開いたページがその2つ目かもしれない。（持ち越していたせいで、タグを付けてそれが2つ目の使用になった瞬間に赤が消えない不具合があった）。走査は本文が変わったときとキャレットが行を移ったときは即座に、それ以外は400ms間隔 |
| **新規ページ作成** | `^o` → 名前を打つ → `＋ …を作成` / 未作成ページへのリンクを `Enter` | どちらもページを開いてそのまま EDIT に入る。**本文を書いた時点で作成**され、タイトルだけなら（打ち換えたとしても）何も残らない。作成は `pageId` を持たない1回の insert として送られ、作成後にサーバの id と行 id を引き取って、その間に打った分を差分で追送する |

## マウス（akapen 同様）

| 操作 | 挙動 |
|---|---|
| ホイール | **ビューポートだけ**を1行ずつ動かす。カーソルは行位置を保ち、画面外に出てもよい。j/k 等のキー移動で追従が復帰する。オーバーレイ上ではリストのカーソルを動かす |
| 左クリック | リンク上ではリンク先へ移動する。それ以外では、その行にカーソルを移動する（選択は解除）。**折り返された行では、クリックした表示行の位置に着く**（列だけで決めると継続行が全部1行目に潰れる） |
| （リンクの当たり判定） | **レンダラが「何をどこに描いたか」を報告する**。行を描くときに、辿れるものごとに「その行の何番目の span か」と行き先（ページ／URL／`code:`・`table:` の書き出し）を記録し、クリックは表示座標を折り返し前の桁に戻して、その桁を含む span を引く。折り返し行は「元の行の何桁目から始まるか」と「ぶら下げインデント何桁を前に持つか」を各行が持っているので、継続行でも正しく引ける。**色は判定に使わない**——以前はクリックされた span の前景色をパレットと突き合わせていて、未作成リンクに独自の色を与えた瞬間、赤いリンクだけがクリックで辿れなくなった。見た目に依存する判定は、見た目を変えるたびに静かに壊れる |
| ドラッグ | READ では押した行からポインタ下の行までを**行**の範囲選択（`v` と同じ。続けて `c` でコメント）。**EDIT に行選択という概念はない**：ドラッグは**文字の範囲選択**で、キャレット（範囲の動く端）がポインタについて行をまたぎ、アンカー（留まる端）は押し位置に残る。元の行へ戻れば範囲はそのまま1行の文字選択へ畳まる。行をまたいだ範囲への入力・`⌫`・`Enter`・ペーストは、いずれもその範囲をテキストとして置換する（行间の融合はテキストエディタと同じ）。上下の端を越えると自動でスクロールする |
| ダブルクリック | READ ではその文字位置にキャレットを置いてセッション開始だけ（遷移のジェスチャに選択は乗せない）。EDIT 中ならその語を選択（英数字・かな・漢字の連なりで、空白や句読点で切れる） |
| トリプルクリック | EDIT 中に行全体を選択。READ からの連打の 3 click 目はセッション内のトリプルとして効く。選択した語・行は `[` でリンク化、`⌫` で削除、文字入力で置換できる |
| （選択の見た目） | 文字選択は**反転表示**で示す。カーソル行はカーソル帯（`DarkGray`）で塗られているので、同じ灰色の背景色では選択が見えない。反転ならどの背景でも contrast が立つ。範囲が行をまたぐと、キャレット行は自行の中の正しい文字範囲まで反転し、残りの被覆行はまるごと帯で塗れる（端が乗っていない行は生ソース表示ではないので、部分選択の細かさまでは描けない） |
| Shift+ドラッグ | **端末自身の文字選択**。マウスを捕捉している間はこれが唯一の「画面の文字をそのまま選ぶ」手段（折り返し行やヘッダも含めて選べる） |
| スクロールバー | トラックをクリックでその位置へジャンプ、サムをドラッグでスクラブ（ビューポートのみ移動） |

ページ送りは **カーソルを動かす**（PgUp/PgDn = 1画面分、`^u`/`^d` = 半画面分、いずれも表示行単位で数えてソース行にスナップ）。ビューポートはカーソルに追従する。

## 意図的に「使わない」キー

- `u` 単独での「戻る」 … akapen の `^u`（半ページ上）との混同を避けナビには使わない → `[`。`u` は vim 同様 **undo** に割当
- `1`〜`9` … 数字は将来の count プレフィックスのために温存。複数リンクはピッカーで選ぶ
- `Space` / `b` … `^d` / `^u` と PgDn / PgUp に統一
- `D`（全削除）… 破壊的操作を大文字1キーに置かない。`d` は akapen 同様「カーソル位置の1件削除」

`j`/`k` 移動 · `Enter` 決定 · `Esc`/`q` 閉じる

（`^o` ページピッカーだけは打鍵がフィルタに入るので、移動は `↑`/`↓` ・ `^n`/`^p`）

## ヘッダ

左に **`プロジェクトの正式名称 / ページ名`**。正式名称は `/api/projects/<name>` の `displayName`
（テーマと同じ応答。非公開プロジェクトで sid が無く読めないときは URL スラッグのまま）。
右端には**状態で、ほかに印が無いもの**だけを ` · ` 区切りで置く：**履歴の位置と書かれた日時**（`4/4 · 日時`。NOW を最後の位置として数え、快照一覧が届くまでは日時だけ。`←` で `3/4 · 快照の時刻` となり、ヘッダと枠が紫になる）、
`未同期`（コミットが失敗した等で手元とサーバーが食い違い、まだ読み直せていない）、`読み取り専用`。
載せないもの：コメント数（`l` の一覧で足りる）、`[✎ 編集中]` と `[ソース]`
（フッターのバッジ・下敷き・キャレットが言う）、選択範囲（フッターの `N 行を選択 …` が言う）、
未読（行頭のテロメアの色が言う）。
幅が足りなければ**右側を優先**する（名前もタイトルも本文側にあるが、履歴位置や日時はここにしか無い）。
左は**まずサイト名を丸ごと落として `/ タイトル`** にし、それでも足りないときだけタイトルを `…` で削る
（サイト名は読者が知っている一語なので、`研…` と残しても意味が無い）。履歴中の順は `3/12 · 日時`（位置が先）。

## 通知（トースト）と状態（ステータス）

フッター右側の1行は**いま何であるか**を言う場所（キーヒント、`選択中 …`、`履歴 3/12 …` の履歴位置、
`… へアップロード中…`、`同期: ws`）。**何かが起きた**ことは、その重さで4段に分けて言う
（対応表は `NOTE-notifications.md`）:

| 段 | 出る場所 | 例 |
|---|---|---|
| 無音 | — （画面自体が答えている） | ページ遷移（ヘッダが変わる）、`s` のモード切替（フッターのタグ）、選択解除 |
| 薄く | フッターのヒント欄に4秒だけ上書き（キーヒントと状態は脇に退く） | `✓ 行3`、`✓ copied`、`保存しました …` |
| 黄バナー | フッターの1行上に中央寄せ、4秒 | `貼り付けは編集中に — e / i / o で入ってから`、`他の人がページを更新しました`、押しても何も起きない理由（`ページの先頭です`、`最も古い履歴です`、`取り消せる編集がありません`） |
| 赤バナー | 同上、8秒 | `コミットに失敗しました …`、`開けません …` |

バナーは場所を予約しないのでレイアウトは動かず、矩形だけが本文の上に乗る。**カーソル行の上には乗らない**（出ている間はカーソル行がその行に入らないよう視界をずらす）。`Esc` で即消える。
新しいバナーは古いものを置き換えるが、フッターの状態を押しのけることはない。以前はこれら全部が
フッターの1行を奪い合っていて、コピーした知らせで選択中のヒントが消えたり、次の通知で前の
通知が上書きされて読めなかったりした（akapen の draw_banner / toast_effect を移植。
フェードは tachyonfx）。

## カーソルとモード切替

カーソルは**ソース行**を指す（akapen の `ViewState.cursor` と同じモデル）。折り返しで複数の表示行に
なった行はまとめてハイライトされ、j/k は表示行単位で送って次のソース行にスナップする。
`z` で view⇄source を切り替えても同じソース行に留まり、その行の**物理画面行**も維持される。
テーブルは **1行 = 1ソース行** でカーソル・選択・コメントが行単位に効く（セルが折り返しても
その行の帰属を保つ。akapen の tui-markdown と同じ帰属モデル）。罫線は直下の行に帰属する。

## ガター・スクロールバー

view / source とも**ページ本文だけを枠で囲み**、関連ページ一覧は枠を閉じた後の下側へ置く。
READ 中は端末の ANSI `DarkGray` を使った枠を表示し、EDIT セッション中は枠を消す。フッターの
`VIEW` / `EDIT` 表示も併用する。`>` は左枠と同じ列に置き、その右隣にテロメア、半角スペース、
本文の順で配置する。このため、カーソル行でもテロメアは隠れない。カーソル行は ANSI `DarkGray` で、
テロメア列から右側のスクロールバー列まで、枠の内側を一続きに塗る。右側のスクロールバーは内容が
収まるときは表示せず、先頭位置でも上枠と重ならない。source モードはガターと本文の間に行番号が入る。
ヘッダーはプロジェクトの Cosense テーマを取得し、Web版の `--navbar-bg` 相当色を使う。半透明色は
OSC 11 で取得した端末背景へ合成するため、ライト端末とダーク端末で明度が自然に変わる。文字色は
合成後のコントラストから黒または白を選ぶ。テーマを取得できない場合は ANSI `Cyan` に戻す。
フッター、枠、スクロールバー、オーバーレイ、関連ページ一覧は固定 RGB 値を使わず、`Green`、
`LightBlue`、`DarkGray` などの ANSI パレットで端末テーマに追従する。本文のリンク、見出し、コード
などには、引き続きシンタックステーマの色を使う。

## 折り返し

**禁則処理**: 行頭に句読点・閉じ括弧・小書きかな・長音（`。、）」ゃっー` など）を置かず、
行末に開き括弧（`（「[` など）を残さない。破れる位置に来たら、**直前の文字を一緒に次の行へ送る**
（追い出し）。端末では枠の外へ文字をぶら下げられないので、送るのが唯一の手。
ただし行を空にしてまでは守らず、句読点が連続する場合は諦める（1文字だけの行が並ぶ方が読みにくい）。


**EDIT のキャレット行も同じようにぶら下げる**。編集中だけ継続行が左端へ戻ると、
書いている場所が視覚的にずれる。クリック位置・`↑`/`↓`・選択の塗り・ハードウェアカーソルは
すべて同じ折り返し（`SessionWrap`）を読むので、描画とキャレットがずれない。
コードブロックの中では、ぶら下げ幅はコード用ガターに揃う。

本文は表示幅で折り返す（CJK 幅対応、`src/wrap.rs`）。箇条書きのレベル1は左端に置き、
レベルが1つ深くなるごとに半角2文字分ずつ下げる。箇条書き（`• `）・コード行の継続行は
**マーカーの右、本文の1文字目の下に揃える**（ぶら下げインデント）。引用（`┃ `）は継続行にも
**縦棒を繰り返す**ので、折り返された引用が1つのブロックとして読める。ネストが深く
継続行の幅が 8 列を切る場合は通常の折り返しに落ちる。source モードは生テキストなので対象外。

## 見出しのレベル操作

Cosense 公式には見出しレベルのショートカットが無い（コミュニティの UserScript が
`Ctrl+8` / `Ctrl+Shift+8` を使っている）。端末では **`Ctrl+8` は 0x7F として届き
Backspace と区別できない**ので、そのままは持ち込めない。

代わりに **`^t` の1キーで循環**させる。`[* ]` → `[** ]` → `[*** ]` → `[**** ]` → 解除 → `[* ]`。
修飾キーの組み合わせを端末に頼らずに済み、「気に入る大きさになるまで押す」という
実際の使い方にも合う。

## 記号の使い分け

TUI では**絵文字を使わない**。多くが2セル幅で、East Asian Ambiguous な矢印類も
フォント次第で幅が変わるため、等幅の桁が崩れる。lazygit や k9s が文字と最小限の記号で
済ませているのと同じ理由。役割を3つに分けて、それぞれ1つの手段で表す。

| 何を伝えるか | 手段 |
|---|---|
| これは何か | 色と文字（`code:名前`、`table:名前`、リンクの色） |
| **押せる** | **下線**。リンクも `code:` も `table:` も添付ファイルも同じ。ただし**一覧（関連ページ・インデックス）では下線もリンク色も使わない**——どちらも「本文の中で押せるものを見分ける」ための印で、1行1リンクの並びでは全行に同じ印を付けるだけになる。見出しと並びがすでに「ここは全部リンク」と言っている。空いた色は**未読**に回す（未読＝テロメアと同じ青／既読＝通常色） |
| 押すと何が起きるか | フッター。カーソル行の `Enter` の行き先が出る |

`▤` や `📎`、`🖼` のような装飾は落とした。同じことを2度言わない。
テーブルの名前行の色も、固定色をやめてシンタックステーマの記法ラベル色（`code:` と同じ）に揃えた。

## メッセージの言語

**画面の文は日本語と英語の両方を持ち、起動時にどちらかを選ぶ**。ステータス行、トースト、
キーヒント、ヘルプ、エラーのすべてが対象。

| 項目 | 内容 |
|---|---|
| 選び方 | `--lang ja\|en` → `COSENSE_LANG` → `LC_ALL` → `LC_MESSAGES` → `LANG` |
| 既定 | 何も指定が無ければ**英語**。環境が何も語らないときは、読める人が多い方を出す |
| 判定 | 値が `ja` / `ja_JP.UTF-8` / `Japanese…` なら日本語、それ以外は英語。空の変数は「答えていない」扱いで次へ進む |

翻訳はカタログファイルに分けず、**呼び出し側に2つ並べて書く**。

```rust
t!("{n} 行削除 · ^z で戻せます", "deleted {n} line(s) · ^z to undo")
```

`error.deleted_lines` のようなキーを作ると、名前を考え、同期を保ち、引きに行く作業が
増える。リテラルを並べておけば、本文と訳を同じ場所で読み、直せる。代償は「メッセージを
足すときは2回書く」ことで、これは両方の読み手に話すための正当な対価と考える。

どちらの言語でも**そのまま残る**のは、言語の単語ではなく**何かの名前**であるもの。

- キー名：`Enter`、`Esc`、`^z`、`j/k`、`⌫`
- フラグと環境変数：`--preview`、`COSENSE_SID`、`GYAZO_ACCESS_TOKEN`、`$EDITOR`
- 記法と形式：`code:mmd`、`table:名前`
- プロトコル・製品名：`websocket`、`OSC 52`、`poll`、`ws`、Cosense、Gyazo、Chrome

そもそも揃える理由は見た目の好みではなく、**同じ行に両方が並ぶ**から。フッターはキーヒントと
ステータスを同じ位置に出すので、一方が英語でもう一方が日本語だと、毎フレームで継ぎ目が
見える。`⌫@行頭 join` のように1つの文字列の中で混ざっている例もあった。

ヘルプのラベル欄は表示幅12桁。日本語は1文字2桁なので、言語ごとに自分のラベルを揃える
（バイト数で揃える書式指定は使えない）。

## Mermaid ブロックの段を動かす

Mermaid の `code:` 行のインデントは、コードの中身ではなく**図そのものの段**を表す
（0〜2段。3段以上は図にならず、全行が普通のリストとして出る）。だから編集中は
この行だけリストの行として振る舞う。

- `code:` ヘッダー行で `Tab` / `Shift+Tab` → **ブロックごと1段動く**（本文の行も
  一緒に動くので、途中で「ブロックが壊れた状態」を経由しない）
- 行頭のインデント上で**スペース**を打つ／`⌫` を押しても同じ（cosense web と同じ作法）
- 2段より深くは行かない。0段より浅くも行かない
- 本文（`flowchart` などの行）の `Tab` は今までどおり**その行だけ**の字下げ。
  あそこではインデントは中身だから
- 編集でソースに戻っている間、1・2段のヘッダー行には**ビュレットが付く**
  （0段には付かない。本文の行にも付かない）

## テーブルの編集

`table:名前` の行と、そこより深くインデントした行がテーブル。**セルの区切りは TAB**
（cosense web と同じ）。編集セッションはテーブルの中にいることを見て振る舞いを変える。

- `table:名前` の行で `Enter` → **最初の行**が開く（1段深いインデント）
- テーブルの行で `Tab` → **右にセルを足す**（インデントではなく TAB を打つ）
- `Shift+Tab` → 直前のセル区切りを取り消す。区切りが無ければインデントを1段戻す＝
  その行がテーブルから外れる
- テーブルの行で `Enter` → 同じインデントで次の行
- **空の行で `Enter` を押すとテーブルから抜ける**（箇条書きのリスト脱出と同じ作法）。
  コードブロックは抜けない — あちらは空行も「空のコード」なので、インデント付きの
  空行はブロックの内側に積める（図の内側に置かれる）。出るのは空行のインデントを
  `⌫` で削り切ってフラッシュにしたとき
- キャレット行では **TAB を `|` の1桁で表示**する。幅0のままだと隣のセルとくっついて、
  キャレットの居場所も見えないため（1文字を1文字に置き換えるので桁の計算は変わらない）
- 深くインデントされた**空の行もテーブルの行**として扱う。入力中の行がそれで、
  cosense も空のセルとして表示する

## ブラケット記法

- `[]` / `[   ]` のように**中身が空のブラケットは記法ではない**。リンク先が無いので、
  Cosense と同じくそのまま `[]` と表示する（以前は丸ごと消えていて、`[]` について
  書いた行から `[]` が消えるという状態だった）
- `[[太字]]` は太字。`[` と `]` を**対で**探す（最初の `]` で切ると `[太字` という
  名前のページへのリンクとして読まれてしまう）。中身は通常の記法として解釈するので、
  `[[[リンク]]]` は太字のリンクになる
- 閉じていないブラケット（`[foo`）はそのまま文字として表示する
- **バッククォートの中は記法として扱わない**。`` `[リンク]` `` と書いた行はリンクを持たず、
  `Enter` でどこにも飛ばない（描画側は元から従っていたが、リンクの抽出と画像の抽出が
  従っていなかったため、記法を説明したページが意図しないリンクだらけになっていた）
- ブラケットは**対応を数えて閉じる**。`[* [ページ]]` や `[[[ページ]]]` のように
  装飾の中にリンクを入れても、リンクとして色が付き `Enter` で辿れる（最初の `]` で
  閉じていた頃は、1つ手前で切れて文字になっていた）
- **米印の数は見出しレベル**。行頭でも文中でも同じで、`[* ]`〜`[**** ]` がテーマの
  Markdown 見出し書式（H4〜H1 相当）に対応する。`[[太字]]` は `[* ]` と同じ扱い。
  `/` `-` `_` はレベルの上に斜体・打ち消し・下線を重ねる
- ただし **太字は全レベル共通の下地**として必ず付け、**斜体は借りない**。
  Cosense の米印記法は「大きさ」より先に**強調**であり、斜体は `[/ x]` という
  別の記法だから、米印だけで斜体になるのは誤ったシグナルになる。
  レベルの差は色（と最上位の下線）で出す。テーマの H4 が斜体だったため、
  米印1個が「太字ではなく斜体」に見えていた

## 見出し

米印が多いほど大きい見出し。`[**** ]` 以上 = レベル1、`[*** ]` = 2、`[** ]` = 3、`[* ]` = 4、
ページタイトル（1行目）= レベル1。各レベルの見た目は **テーマの Markdown 見出し
（`markup.heading.N.markdown`）の書式そのまま**（色＋太字/斜体/下線）。akapen で同じテーマの
Markdown を開いたときと同じ見え方になる。テーマが書式を指定していないレベルだけ、akapen と同じ
構造的な修飾（1: 太字＋下線 · 2: 太字 · 3: 太字＋斜体 · 4: 斜体）を補う。
そのうえで**米印記法では常に太字を足し、斜体は落とす**（Cosense の米印は強調記法で、
斜体は `[/ ]` の担当のため）。
先頭空白と見出し記法が同じ行にある場合は、インデント位置に `• ` を表示し、本文には見出しの
テーマ書式を適用する。箇条書きと見出しを排他的には扱わない。

`--theme NAME` は本文全体に効く（akapen 同様）。コードブロックのハイライトに加え、見出し・リンク・
引用・`code:` ラベルの色をテーマの **Markdown スコープ**から引く（`[**** ]`〜`[* ]` → `markup.heading.1..4`、
リンク/`#タグ`/URL → `markup.underline.link`、引用 → `markup.quote`、`code:` → `markup.raw.inline`、
**未作成ページへのリンク → `markup.deleted`**）。未作成リンクに `invalid` を使わないのは、埋め込みテーマを
実測したところ `invalid` のほとんどが**背景色**の指定で（Solarized・Dracula・Nord・Monokai・OneHalfDark）、
前景色を借りると本文と同じ色になってしまうため。`markup.deleted`（diff の削除行）はどのテーマでも
前景の赤系で、意味も「そこには無い」で一致する。
**`#タグ` はリンクと同じ色**で描く。`#foo` と `[foo]` は同じページで、Cosense も両方を
`.page-link` として同じように描いている（`app.css` にハッシュタグ専用の規則は1つも無い。未作成の
`.empty-page-link` も共通）。`#` が既に「どの記法で書いたか」を言っているので、色を分ける必要がない。
（以前は緑だったが、あれは TypeScript 試作の `chalk.green` の名残で、しかもテーマが
`markup.underline.link` を持つかどうかで緑になったりリンク色になったりしていた）

テーマにそのスコープの定義がない構文は、端末背景（OSC 11 で自動判定、`--light`/`--dark` で強制）に
合わせた既定色に落ちる。見出しは書式ごと、それ以外は色だけを借りる。
テロメア・カーソル・選択の色はテーマに依存しない。

## テロメア（行の鮮度）

各行の左端1列（ガター）に、Scrapbox 同様のテロメアを表示する。**太さ = 編集の新しさ、色 = 自分が既読か**。

- **未読行**（自分がそのページを最後に開いた後に編集された行、初めて開くページの全行）: **経過時間に関係なく青**。古いほど少し落ち着くが、グレーにはならない
- **既読行**: 太さはそのまま、色はグレー（1年超はさらに薄いグレー）
- 初めて開くページは全行未読（Scrapbox と同じ）。数はどこにも出さない（テロメアの色で足りる）

「最後に開いた時刻」は Cosense API の `lastAccessed`（ブラウザでの閲覧）と、この viewer のローカル記録
（`$XDG_STATE_HOME/cosense-tui/visits.json`、既定 `~/.local/state/…`）の新しい方を使う。<br>view / source どちらのモードでも表示される。

段階（太→細）: `█` `<1h` · `▊` `<1d` · `▌` `<1w` · `▎` `<30d` · `▏` `<1y` · `▏` それ以上<br>いずれも1セル幅・左寄せのブロック要素なので、本文の幅は変わらず左端も一直線に揃う。

## 画像の表示規則

- **画像になるのはブラケットで囲まれたときだけ**（`[https://…/a.png]`、`[https://gyazo.com/…]`）。
  裸の URL は行頭にあってもリンクのまま。cosense web と同じ規則で、以前は「行頭に画像 URL が
  あれば画像」と判定していたため、**その行の残りのテキストと2枚目以降の画像が消えていた**
- 画像だけの行はその画像1枚になる
- **テキストと画像が混ざった行は、書いた順に横へ並べる**。端末の画像は自分が覆うセルしか
  占めないので、その左右には文字を書ける。画像は**下端をテキストの行に揃えて上へ伸ばす**
  （ブラウザのインライン画像と同じ）。`本文 [画像]`・`[画像]本文`・`[A] と [B]` は
  すべて同じ仕組みで、特別扱いを分けない
- 幅が尽きたら次の行に送る。送った先も同じ規則で、その階層の列から並べ直す
- **混ざった行のリンクもクリックで開ける**。レイアウトが文字の片ごとに「どの部品の
  何列目から」を覚えているので、押されたセルをレンダラの Hit（テキスト部品を通した
  スパン番号）へ逆引きする。画像の右の文字も、折り返して下の箱に落ちた文字も同じ道。
  以前はレンダラが Hit を捨てていて、このような行だけ押しても何も起きなかった
- **インデントされた行は、画像が混ざってもビュレットを失わない**。`•` はその行の
  **左上**（画像がどれだけ高くても行の始まり）に置く
- テキスト行には URL の全文ではなく `🖼 ファイル名`（gyazo は `🖼 [gyazo]`）と出す。
  絵は下にあるので、行は「そこに画像がある」とだけ言えばよい
- **リンク付き画像 `[リンク先 画像URL]` は1つのリンク**。画像がラベルで、`Enter` はリンク先へ。
  URL ごとに1件ずつ拾っていた頃は選択肢が2つ出て、しかも互いのラベルが入れ替わっていた
- **画像だけの行がインデントされていれば、それは箇条書きの項目**。`•` をその階層の
  位置に置き、画像は**その階層の本文が始まる列**（上下の行の文字と同じ列）から描く。
  cosense では箇条書きの下にも画像が貼られ、ビュレットの右に画像がある状態が普通にあるため
- **テキストの下にぶら下がる画像にはビュレットを付けない**。項目の実体は上のテキスト行で、
  画像はその続き。列だけ本文に揃える
- 読み込み中のプレースホルダとエラー表示も同じ規則に従う
- 編集中に URL を貼ると必要なブラケットを補う。画像 URL は `[URL]`、
  文字を選択した状態なら `[選択した文字 URL]`（リンクのラベルになる）。
  画像でない URL をそのまま貼った場合は何も足さない

## 画像の大きさ

- 幅は最大 64 桁（ペインが狭ければその幅）
- **高さは最大 20 行**。それを超える画像は形を保ったまま縮小する。ブラウザなら縦に長い
  スクショもそのまま置けるが、端末では行が希少なので、1枚で画面を占有させない
- **高さは行数を切り捨てて測る**。最終行が半分しか埋まらない画像は、その行を持たない。
  余った半端を残すと、下端に揃えたテキストのベースラインが画像より一段下に見える

## 画像の描画方式

既定は端末に問い合わせた最良の方式（`auto`）。**画質を優先する**。
いま何で描いているかは起動時のステータス行の `image:` に出る（`kitty` / `iterm2` / `sixel` / `halfblocks`）。

画素で描く方式（sixel / iTerm2）は端末エミュレータが直接描くので、マルチプレクサの
ペインの重なりを知らない。別のペインを重ねても画像が前面に残ることがある。
一方 **kitty の画像は Unicode プレースホルダ**（セルに紐づく置き方）で描いているので、
クリップもスクロールも文字と同じに従う。重なりで困るときは、まず端末が kitty graphics を
話せるかを確認するとよい。

- `COSENSE_IMAGE=kitty` … kitty graphics を明示する。**マルチプレクサと併用するならこれが本命**。
  Unicode プレースホルダで置くのでセルに紐づき、重なりもスクロールも文字と同じに従い、
  しかも画質は落ちない（Ghostty・kitty・WezTerm・foot などが対応）
- `COSENSE_IMAGE=iterm2` / `sixel` … 端末がそれしか話せないとき。画素で描くので
  マルチプレクサのペインの重なりは正しく処理されない
- `COSENSE_IMAGE=halfblocks` … 文字セルとして描く。重なりは完全に正しくなるが、
  1セル2画素まで落ちるので画質は大きく劣化する。最後の逃げ道
- `COSENSE_IMAGE=auto`（既定） … 端末に問い合わせた方式

重なりで困ったら、まず `image:` が何になっているかを見る。`iterm2` や `sixel` なら
`COSENSE_IMAGE=kitty` を試す価値がある（端末が対応していれば画質はそのままで直る）。

## 画像読み込み

画像は**バックグラウンドで並行ダウンロード・デコード・端末プロトコルへエンコード**される
（メインスレッドは受け取って差し込むだけなので、読み込み中も操作は止まらない）。ページは即座に読め、届いた画像から
順に差し替わる（同時にダウンロードするのは4枚まで——一斉に撃つとサイト全体のレート制限に当たり、次の一覧取得が 429 で断られる。API 呼び出しは 429 を受けたら `Retry-After`（無ければ 1s→2s→4s）だけ待って最大4回まで言い直す。未到着の間は**書かれたままの `[URL]` を1行**で見せ、mmd の描画待ちと同じ明るさの帯を今度は横に走らせる。届いたら画像に置き換わる——図がコードを置き換えるのと同じ動き。文字と画像が混ざる行の未到着分は、隣の文字が跳ねないよう箱を確保したうえで、**その箱の下の行（本文のベースライン）に `[URL]` を出す**——空き箱だけでは「何が来るのか」が読めない。帯は**行の幅に関係なく約1.2秒で1往復**（縦の帯は「行/秒」だが、横で行/秒を使うと60列のURLが10秒かけて這い、ダウンロードの方が先に終わって止まって見える）。**2回目以降は `~/.cache/cosense-tui/images/` から読むので帯は出ない）。
gyazo に加え、任意の http(s) 画像 URL（拡張子つき）とリンク付き画像 `[href 画像URL]` に対応。

## Mermaid 図の描画（Web renderer）

`code:mmd` / `code:mermaid` / `code:<名前>.mmd` のコードブロックは、**図として表示**される。

描ける型(flowchart・sequence・pie・gantt・gitGraph・class・er・journey・mindmap・
timeline・xychart 他)はまず**罫線・表のテキスト描画**(`mermaid-text` による)で出し、
描けないものだけ素のコード行に落ちる。**テキスト描画が本流**で、ブラウザ描画は既定で**オフ**
(`COSENSE_WEB_RENDER` の既定)。Chrome の起動も、キャッシュ I/O も、非公開ページ用の
sid も不要になる。ブラウザが描いた本物が必要になったら `COSENSE_WEB_RENDER=manual`(ページごと
`R`)か `=auto` で上げる。ページごと見るだけなら `w` で web を開くほうが早い。
テキスト描画は即時・オフラインで、
選択・検索・コピーが効く。**編集中のブロックは、ソースの下に図のライブプレビューを
出す**（打鍵のたびに追従。全行に薄い左罫 `▏` と薄字「プレビュー」——本文と読み違え
させない印。組めない式・幅に入らない式は黙る）。`COSENSE_MERMAID=off` で
テキスト段を止めて以前の振る舞い(画像 → コード行)に戻せる。フォントに罫線グリフが
無い等で崩れるときは `COSENSE_MERMAID=ascii`(`+ - | > <` だけで描く)。

## 数式の描画

`code:tex` / `code:latex` / `code:<名前>.tex` のコードブロックは、**数式として組まれる**
(`term-maths` による。分数・根号・積分・行列・ギリシャ文字など)。図と同じく
即時・オフラインで、選択・検索・コピーが効く。編集中のブロックは素のソースに戻る。
図と違って入れ子にできない。**箇条書きのインデントが1段でも付いたら数式ではなくなり**、
`code:tex` の行も中身の行も普通のリストの行になる(mmd の3段目以降と同じ)。
また図と違って**ブラウザ画像の段は無い**ので、lib が読めない式(`\begin{align}` など)と
ペイン幅に入らない式はコードブロックのまま出る。`COSENSE_MATH=off` でテキスト段を止められる。
インラインの `[$ ... ]` も組む。1行で済む式はその場で置き換え(`[$ E = mc^2 ]` → `E = mc²`)、
分数・根号・積分のように背の高い式は**本文の行をまたいで**描く——分子は上、分母は下、
前後の文は真ん中の行に並ぶので、1つの文として読める(行内画像と同じレイアウト)。
ペインが狭くて入らないときだけ LaTeX に戻る。

## 編集中のライブプレビュー

図と数式は、編集セッションがブロックの中にいる間、**ソースの下にいま打っている内容の
組図を出す**（cosense web と同じ。キーストロークのたびに再組図 — 実測 0.4ms なので
打鍵のたびで足りる）。インラインの `[$ ... ]` も同様で、行の編集中は行の中の全数式を
**横に並べて**組む。どちらも違いの演出は、プレビューの全行に付く**薄い左罫 `▏`** と、
先頭の薄字ラベル「プレビュー」。lib が組めない式・ペイン幅に入らない式は黙る（ソースが
もう見えているので、何かを出す必要がない）。プレビューは添え物なので、カーソル帯も
選択もカーソル自身も乗らない。コードブロックの中はインラインプレビューを出さない
（`[$ ]` はただの文字）。

## Mermaid の描画の仕組み

Mermaid には「ソース → SVG」の公開 REST API がない。Cosense はブラウザ側でハッシュ付きの Mermaid
チャンクを動的 import して `.mermaid-preview` に SVG を差し込んでいる。そこで TUI 側で Mermaid を
再実装するのではなく、**ヘッドレス Chrome で実際の Cosense ページを開き、Cosense 自身が描いた
DOM 要素を PNG で切り出す**（`cosense::webrender` / `cosense::chrome`）。将来 TeX・`.icon`・
ProjectCSS つきブロックも同じ経路に載せられる。

- **描画は完全にバックグラウンド**。ブラウザの起動・待機・撮影は専用ワーカースレッドが行い、
  UI スレッドは一切待たない。図が届くまで（届かなければずっと）**元のコードブロックがそのまま出る**。
- **依存**: Chrome / Chromium / Edge / Brave のいずれか。macOS の `/Applications/…` と `PATH` を
  自動検出する。`COSENSE_CHROME=/path/to/chrome` で明示指定できる（指定したものが無ければ
  他のブラウザに勝手に落ちない）。
- **private project**: ブラウザには `connect.sid`（`--sid` / `COSENSE_SID`）だけを CDP の
  `Network.setCookie` で渡す。argv・ログ・エラー表示・キャッシュキーには一切載らない。
  public project は SID なしで動く。
- **Web artifact の描画は既定でオフ**。上げるには `COSENSE_WEB_RENDER=manual`(`R` で描く)か
  `=auto`(読み込み時に描く)。ブラウザの起動は
  このビューアが行う中で最も高価な操作なので、manualではページを開いた時点で**ディスクキャッシュに
  あるものだけ**を表示する。cache miss は `R` で1バッチまとめて描画する。Mermaidだけでなく、
  将来のTeX・`.icon`・ProjectCSS描画も同じキーを使う。manualではソース編集後もChromeを
  自動起動せず、新しいartifactがcacheになければソース表示へ戻る。`auto`はページ表示時と
  ソース更新後に自動描画する。offではワーカー・バックエンド・cache I/Oを一切動かさず、
  Chrome の検出も行わない。
  EDITセッション中の`R`は通常の文字入力。
- **ブラウザの保温**: バッチの後 15 秒はブラウザを生かしたままにする（温まったブラウザでの
  再描画は約 2 倍速い）。`COSENSE_WEB_IDLE_SECS=0..300` で変更でき、`0` はバッチごとに終了。
- **フォールバック**: ブラウザが無い・SID が無い/失効・タイムアウト・Mermaid の構文エラーの
  いずれでもクラッシュせず、コードブロック表示のままステータス行に短い理由を出す。
- **auth は 1 つの真偽値ではない**: REST（PAT / サービスアカウント / SID）、push sync、
  ブラウザ描画、project の公開/非公開を別々の軸として持つ。**SID が無い・失効していても
  PAT が生きていれば読み書きは一切変わらない**。SID 無しの場合:
  - public project → cookie を送らない **anonymous 描画**が動く
  - private project → ディスクキャッシュにある図だけ出し、無いものはソースのまま。
    ページにつき一度だけ「非公開の図を描画するには connect.sid が必要です」と出す
  - 公開/非公開が判定できないとき → 自動では描画せず、`R`を押したときだけ一度試す
  SID があるのにブラウザがログイン画面へ飛ばされた場合、public なら cookie を捨てて
  一度だけ匿名で描き直し、private なら**描画だけ**諦める（編集は動き続ける）。
- **更新の反映**: `connect.sid` があれば websocket の push sync を試みるが、**繋がって
  room に join し、join 後の追いつき取得まで成功して初めて**保険ポーリングを 60 秒へ緩める。
  それまでと、切断・再接続中は 3 秒ポーリング。失効した SID で最大 60 秒黙る、という
  以前の穴はこれで塞がっている。ステータス行の `sync:` は `poll` / `ws` / `reconnecting`。
　フッターは**新しい状態を映せていない理由だけ**を出す。`ws` で滞りが無ければ何も出さない。
　`同期: poll` は web 側の編集が最大3秒遅れて届くこと、`⟳ n 件…` は**既に届いた更新が待っている**
　ことを意味する。待つのは編集中の行が未コミットのときで（未保存の行にリモートの状態を被せない）、
　その場合は「編集中の行を待っています」と出る。行を離れるかコミットが終われば即座に適用される。
- **狭いペインでは図をペイン幅に収める**: 描画はペインのテキスト幅でクリップされるので、
  ペインより広く符号化された画像は右側が黙って消える。写真なら切れても写真だが、
  切れたフローチャートは意味を失う。よって図は `min(テキスト幅, 64)` 桁で符号化し、
  ペインがその上限をまたいだら**キャッシュ済み PNG から符号化し直す**（デコードと縮小のみ、
  ブラウザは使わない）。新しい符号化が届くまで古い絵をそのまま出すので、ソースへ
  戻ってちらつくことはない。通常の画像は従来どおり 64 桁固定で、この対象外。
- **エラー表示はキーヒントを奪い続けない**: 図の失敗メッセージは 6 秒でステータス行を明け渡す。
  ただしその間に他の処理がステータス行へ書いていたら、そちらを尊重して何もしない。
- **リサイズでは再描画しない**: ビューアは画像を自前のセル幅にスケールして表示する（ペイン幅は
  見ない）ので、ブラウザ側のビューポート幅はラスタの精細さしか決めない。よって描画は
  固定幅 1000 CSS px で行い、**キーに幅を含めない**。以前は幅をキーに入れていたため、
  10 桁ほどリサイズするたびに 3〜6 秒の再描画が走り、ウインドウ枠をドラッグすると
  通過した幅の数だけバッチが積まれて（ワーカーは 1 バッチずつ直列処理）最終幅が
  最後尾に回り、「いつまでも読み込まれない」状態になっていた。
- **キャッシュと世代管理**: `project / title / pageId / lineId / そのブロック自身のソースのハッシュ /
  テーマ` で 1 つの図を同定する。ページ全体の commitId は**使わない**——commitId は改行 1 つでも
  動くので、無関係な行を編集しただけでページ内の全図が再描画されてしまう。ブロック自身のテキストは、
  そこから生成される絵とちょうど同じ粒度で変わる。ページ移動は世代番号で弾くので、**古い図が
  新しいページに出ることはない**。PNG は `~/.cache/cosense-tui/webrender/` に残る。
- **描画中のフィードバック**: そのコードブロックが少し暗く落ち、**上から下へ明るさの帯が流れる**。
  テキストは動かないので読んだまま待てる（スピナーのように場所を奪わない）。描画が終わるか
  失敗すると帯は止まり、通常の表示に戻る。ハイライト色は端末背景に向けて混色して明度を作るので、
  テーマの色そのものは変えない。パレット色（`DarkGray` など）は RGB を持たないので、xterm 既定値で
  擬似 RGB に直してから同じ混色をする（DIM 属性だけの切り替えだと、もともと暗い行では帯が読めない）。
  source 表示（`z`）では絵が出ないので帯も出ない。
- **EDIT 中**: 待たされるのは**キャレットが乗っているブロックだけ**。その 1 行はまだ
  コミットされていない（ブラウザはサーバ上の内容しか見られない）ため描画を保留するが、
  ページ上の他の図は編集セッション中でも普通に描画される。キャレット移動のたびに
  dirty 行はコミットされるので、**そのブロックから離れた時点で描画が始まる**。
  コミットが飛んでいる間（`inflight > 0`）はページ全体で描画を止める——飛んでいるコミットが
  図を変えるものかもしれないため。
  セッションがそのブロックの行に入ると図は引っ込み、生ソースが出る。編集の契約（行単位の
  生テキスト編集）は図があっても変わらない。図が差し込まれてもカーソル行は画面上の同じ
  位置に保たれる（既存の `relayout_preserving_screen_row`）。
- **タイムアウト**: 既定 25 秒（`COSENSE_WEB_TIMEOUT=<秒>`）。描画が止まって 6 秒進展が無ければ
  待つのをやめるので、1 つ壊れた図が他の図の表示を遅らせない。
- **速度**: ページ 1 枚あたり初回 5〜6 秒、再描画 2〜3 秒（図の数によらず、1 ページ 1 回の
  ナビゲーションでまとめて撮る）。うち 3.5 秒程度は Cosense 自身のページ起動なので短縮できない。
  ブラウザはバッチ間で**起動したまま保持**し、90 秒何も来なければ自動的に閉じる（Chrome の
  HTTP/V8 キャッシュが温まるため、再描画が約 2 倍速い）。同じ図の 2 回目以降はディスク
  キャッシュから即座に出るので、ブラウザは起動しない。
- 動作確認用: `cargo run --bin web_smoke -- <project> <title>`（テストスイートには入らない）。
  `COSENSE_WEB_DEBUG=<ファイルパス>` で各フェーズの所要時間をそのファイルへ追記する。
  レンダリングは TUI が alternate screen を握っている間に別スレッドで走るので、
  stdout / stderr へは一切書かない（画面が壊れるため）。

## コードブロックの編集

`code:名前` の行とその1段深いインデント行が1つのコードブロックになる（cosense web と同じ規則）。
TUI の編集セッションもこの境界を見て振る舞いを変える。

- `code:名前` の行で `Enter` を押すと、**ブロックの本文行**（1段深いインデント）が開く。
  これが無いと新しいコードブロックを作れない（新しい行がインデントなしで始まり、
  レンダラがコードとして読まないため）
- ブロック内の空行で `Enter` を押しても**リスト脱出は起きない**。インデントを保って
  ブロック内に留まる。抜けるときはインデントを削る
- ブロック内ではキャレット行に**ビュレットを表示しない**。先頭の空白はコードの内容であり、
  アウトラインの階層ではないため。キャレットの桁計算も1対1になる
- ブロックかどうかは**入力中のテキスト**で判定する。`code:` と打った時点でその下の行の
  ビュレットが消え、コミットを待たない
- ブロックの範囲は**うっすい背景**で示す。色は端末の背景を数%だけ動かしたもので、
  ライト端末では少し暗く、ダーク端末では少し明るくなる。シンタックステーマの色は
  使わない（本文と地続きの帯なので、テーマ由来の色だと画面に貼られた別色の矩形に見える。
  ヘッダーが端末背景へ合成しているのと同じ理由）。カーソル行と選択範囲の帯が優先される

## コピー

コピーされるのは**Cosense のソース**（インデント・`[]`・`code:` を保ったまま）。
別のページやエディタに貼って、そのまま元の構造に戻せる形を優先している。
EDIT 中のキャレット行は**画面に見えているテキスト**（未コミット分を含む）をコピーする。

| 対象 | READ | EDIT |
|---|---|---|
| カーソル行 / 選択範囲 | `y` | `^y`（`y` は文字入力になるため） |
| ページ全体 | `Y` | — |
| コメント全件 | `l` でコメント一覧を開いて `y` | — |

コピー先の決め方:

1. ローカル実行時は `pbcopy` / `wl-copy` / `xclip` / `xsel` の順に試す
2. SSH 越し（`SSH_TTY` / `SSH_CONNECTION`）では**必ず OSC 52**。ローカルのコマンドは
   接続先のクリップボードに書いてしまい、手元には届かないため
3. tmux 内では OSC 52 を passthrough で包む。tmux 側の `set -g set-clipboard on` が要る
4. どれも通らなければステータスにその旨を出す（黙って失敗しない）。OSC 52 は端末側の
   上限があるので 48KB を超えるコピーは送らない
