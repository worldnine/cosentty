# EDIT の選択（マウス・キーボード）

## 結論

EDIT の選択は「行をまたぐ文字範囲」に一本化した。行 band の概念は EDIT から無くなり、行単位の範囲選択は READ の専売になった（`v` / Shift+↑↓ / ドラッグ → `c` コメント）。機能としては実現できているので、このまま据え置く。

残っているのは**表現**だけ。行をまたいだ選択の見た目がユーザーに伝わらない（後述）。全体の見直しを入れる。

## 至った経緯（コミット順）

- `1ce3666` 行をまたぐマウスドラッグのクラッシュ修正。原因は、アンカー行のテキスト基準で算出したキャレット（バイト位置）を、行をまたいだドラッグの最中にセッションが座り替わった**別行のバッファ**へ代入していたこと。日本語本文だとマルチバイトの途中でスライスして次の描画で panic した（`byte index 5 is not a char boundary; it is inside 'い'`）。併せて `display_caret` / `raw_caret_from_display` / `SessionWrap::row_col` を文字境界へ floor する安全網を入れた。同じコミットで EDIT 中のダブルクリック語選択・トリプルクリック行選択を追加。
- `16b3636` VIEW→EDIT 遷移のダブルクリックは「キャレットを置くだけ」に戻した。遷移ジェスチャに語選択を乗せるのは驚き。
- `01e8b2d` 「EDIT から行 band を消す」第一段階として、ドラッグの選択を押した行だけに残すクランプ方式にした。が、行をまたいで選択できなくなるという本末転倒の指摘をうける。
- `c839924` 最終形。`EditSession::sel_from` に `(line, byte)` のアンカー位置を持たせ、キャレットを範囲のもう一方の端とする。マウスドラッグでも Shift+↑↓ でも、選ばれるのは同じ「行をまたぐ文字範囲」だ。印字・`⌫`/`Del`・`Enter`・ペーストは範囲をテキストとして置換する。行をまたげば行が融合する、テキストエディタと同じ契約で、構造編集なので 1 コミット 1 Undo。`^y` は範囲のテキストを改行交じりでコピーする。

## 現在の挙動とコードの場所

すべて `src/bin/view.rs`。

| 要素 | 場所 |
|---|---|
| 選択のモデル（`sel_ends` / `sel_span` / `caret_sel_bytes`） | `EditSession` の impl（`sel_from` フィールド直後） |
| 範囲の置換コア（入力・`⌫`・ペースト） | `session_replace_selection` |
| Enter で範囲を区切り1つに | `session_enter_selection`（`session_split` の先頭から呼ぶ） |
| マウス（Down / Drag / Up / クリック回数） | `handle_mouse_content`、`register_click`、`word_span` |
| 「このキーは選択を維持する」ガード | `handle_session_key` 冒頭の `keeps_span`（Esc・Enter・BS・Del・`^y`・Shift 矢印・印字キー） |
| キャレット行の生ソース描画と反転 | `content_view` の `raw_rows`（`Modifier::REVERSED`） |
| 被覆行の帯 | `draw` の `sel_range`（`sel_ends` から行の範囲を算出） |

仕様の要点は次の通り。

- READ→EDIT 遷移のダブルクリックは無選択。EDIT 中のダブルクリックで語（英数字・かな・漢字の連なり、`word_span`）、トリプルで行全体
- 行をまたいだドラッグでキャレット（セッション座席）はポインタに追随する。元の行に戻れば範囲はそのまま1行の文字選択に畳まる
- タイトル行に及ぶ範囲の置換は、タイトル行のテキストを変えるが行そのものは消さない（キャレット行への join と同じ挙動）
- 回帰テスト: 描画を挟んだ往復ドラッグは `a_drag_that_wobbles_across_lines_stays_characters`
- 行をまたぐ範囲の選択とコピーは `the_mouse_in_edit_selects_characters_across_lines`
- 入力・置換・Esc の反応は `a_cross_line_selection_reacts_like_a_textareas`
- 範囲からの改行は `enter_replaces_the_range_with_one_break`

## これからの課題（表現の見直し）

1. **行をまたいだ選択が伝わらない**。キャレット行は精密な REVERSED が出る一方、アンカー行と途中の行は帯（`SEL_BG`）だけ。しかも `SEL_BG` は `CURSOR_BG` と同じ `DarkGray` で、キャレット帯と区別がつかない。「帯は選択です」を名乗れていない。候補:
   - EDIT の被覆帯だけカーソル帯と別の色にする（構成は変えない最小案）
   - 被覆行をキャレット行と同じ生ソース表示に繰り上げ、範囲のバイトを精密反転する。一度実装して検証まで通ったが、選択中にだけ角括弧が現れるといった見た目の跳ね方が大きく、未コミットのまま破棄した。この節の記録から組み直せる
   - akapen・本家の選択表示を引き写す設計ごとやり直す
2. **精密な部分反転が生ソースの行にしか載せられない**。ビュー表示（装飾後）の span とソースバイトの対応をレンダラが保持していないため。選択表示に限らず、下線の当たり判定など「表示位置 → ソース位置」が要る話の共通前提になる。`Hit`（辿れる span の記録）と同じ系統で、span ごとのソース範囲を持たせるのが本命。
3. 範囲が行をまたぐとき、テーブル行・`code:` ブロック内・mermaid 被覆行での見え方は帯止まり。生ソース化した場合のガター（コードのえぐり、タブマーカー）との合わせ技は未検証。
4. 選択はページ離脱・リモート編集の適用で畳まれる。本家もそうなので畳んでよいが、編集中の ws 適用時に選択が生き残るケースのテストは無い。
